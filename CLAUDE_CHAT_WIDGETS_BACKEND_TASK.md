# CLAUDE_CHAT_WIDGETS_BACKEND — задание Codex (бэк для «апп в чате»)

> Автор: Claude. Дата: 2026-07-19. Контекст: клиентский апп «Мужская Эстетика»
> (легаси-бэк: Python `get_ai_response` + `api-proxy.php` + YClients 503759).
> Фронт уже показывает в чате инлайн-виджеты (запись/мои записи/баллы/магазин/
> профиль/история/друзья/уведомления). Всё, что ниже — БЭК, которого не хватает,
> чтобы «весь апп жил в чате». Оплаты услуг НЕТ и пока не будет — её не делаем.

## 1. 🔴 Умный триггер виджетов — поле `widget` в ответе чата
Сейчас фронт открывает виджет по regex-эвристике в `send()`. Нужно, чтобы **Майя сама**
решала, какой виджет показать, по любой формулировке и своими словами.

- В ответе `?action=chat` и в SSE `?action=chat_stream` добавить необязательное поле
  `widget` (строка) рядом с `reply`. Допустимые значения (совпадают с фронтом):
  `book | mybookings | loyalty | shop | profile | history | referral | notify`.
- Пример: клиент пишет «хочу привести себя в порядок к субботе» → Майя отвечает тепло
  + `widget: "book"`. «сколько у меня бонусов» → `widget: "loyalty"`.
- Модель должна возвращать `widget` ТОЛЬКО когда виджет реально уместен (не на каждый
  ответ). Пустой/отсутствующий = обычный текстовый ответ.
- Фронт после этого: Claude добавит приём поля `widget` в чат-ответе и отрисовку карточки
  (сейчас готов рендер всех 8 виджетов). Regex-эвристику оставим как фолбэк.

## 2. 🔴 Реальная отмена записи клиентом (и перенос)
Сейчас в легаси НЕТ клиентского эндпоинта отмены/переноса — виджет просит Майю отменить
текстом. Стас хочет отмену **как настоящую функцию клиента**.

- Новый action, напр. `?action=client_cancel_record` — принимает `record_id` (и 3-канальную
  авторизацию клиента, как `cabinet_me`), проверяет, что запись принадлежит этому клиенту,
  и отменяет её в YClients 503759 (delete record). Ответ: `{success:true}` или коды
  `too_late_to_cancel | not_found | not_yours`.
- Аналогично `?action=client_reschedule_record` — `record_id` + новые `date`+`time`
  (неразрушающий PUT `record/{company}/{id}`, как в правилах проекта). Ответ с теми же кодами.
- Плюс: пусть `cabinet_me` в `upcoming[]` возвращает `record_id` у каждой записи (сейчас
  фронт-виджет «Мои записи» читает `upcoming`, но id для отмены нужен явно).
- Фронт после этого: Claude заменит «просьбу Майе» на прямой вызов + подтверждение в виджете.

## 3. 🟡 Проактивная Майя (Майя пишет первой) — по видению Стаса
Механику доставки предложи сам (сообщение в ленту чата с полем `widget`, либо push,
который открывает чат с готовой карточкой). Нужны сценарии:

1. **Напоминание о записи** — за N часов до визита: «Напоминаю: завтра в 15:00 у Ильи 👇»
   + виджет записи/переноса.
2. **Баллы → на что потратить (Уход)** — зная баланс клиента, подсказать доступные
   ДОП-услуги из категории **«Уход»** (коррекция воском, массаж, спа, скраб и чёрная маска,
   уход за кожей головы, патчи — всё под заголовком «Уход» в YClients). Пример: «У вас
   1500 баллов — хватит на массаж и патчи 👇». Майе нужен каталог «Уход» с ценами + баланс
   в контексте (или готовый расчёт «что по карману»).
3. **Давно не был на стрижке** — если с последнего визита прошло > X недель: «Давно вас не
   видели — записать как обычно к [мастеру]? 👇» + виджет записи.
4. **Оставить отзыв** — после завершённого визита предложить оставить отзыв (куда ведём —
   Яндекс/2ГИС/внутренний — уточни у Стаса; фронт покажет CTA-карточку).

- Отрисовка проактивных карточек, приходящих с бэка.
- Виджеты Друзья/История/Уведомления/Магазин/Профиль/Баллы/Запись — уже готовы на легаси.
