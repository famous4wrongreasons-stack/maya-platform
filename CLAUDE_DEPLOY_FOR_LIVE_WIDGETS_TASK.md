# CLAUDE_DEPLOY_FOR_LIVE_WIDGETS — задание Codex (блокер живых виджетов)

> Автор спеки: Claude. Дата: 2026-07-19.
> Цель: чтобы Стас получил на телефоне (нативка) И в PWA работающий чат MAYA с
> живыми виджетами (запись/магазин/профиль). Фронт-виджеты готовы и проверены;
> сейчас им не с чем разговаривать, потому что SaaS-бэк нигде не задеплоен.
> Это задачи, которые зависят от Codex (+ инфра-решения Стаса).

## Контекст

- Виджет записи в чате уже собран и проверен на стенде (ветка `claude/chat-booking-widget`,
  коммит `b7fe2547`): `ABookCard` ходит в боевые эндпоинты через мост
  `window.__meSaasAuthedFetch` — `/staff`, `/services`, `/available-days`,
  `/available-slots`, `/appointments[/preview]`. На стенде (:3107, mock-CRM тенант)
  весь путь staff→services→days→slots→preview = OK.
- Проблема: SaaS-бэк (NestJS) живёт только на `localhost:3107`. С телефона и с
  прод-домена он недостижим. Легаси-апп «Мужская Эстетика» на телефоне ходит в
  YClients/Python — это ДРУГОЙ бэкенд.

## Что нужно от Codex (по приоритету)

### 1. 🔴 Публичный деплой SaaS-бэка (главный блокер)
- Поднять NestJS-бэк на публичном HTTPS (домен + SSL), managed Postgres, секреты в env.
  Ранбук уже есть: `CODEX_PROD_DEPLOY_AND_OAUTH_RUNBOOK.md`.
- Результат: стабильный публичный API base, например `https://api.<домен>/api`,
  доступный и с телефона, и из PWA. Дать Claude этот URL.
- ⚠️ Требует решений/доступов Стаса (сервер, домен, секреты) — согласовать с ним.

### 2. 🔴 Тенант с данными для записи
- Завести тенант, на котором будут работать виджеты: либо «Мужская Эстетика» как
  SaaS-тенант, либо демо-тенант.
- У тенанта включить фичу `booking` и подключить источник данных: **CRM** (YClients/
  Altegio реальный, или mock для демо) ЛИБО внутренний календарь с мастерами/услугами/
  расписанием. Без этого `/staff`, `/services`, `/available-slots` вернут пусто/ошибку.
- Проверить: `GET /staff`, `/services`, `/available-days`, `/available-slots` отдают
  данные; `POST /appointments/preview` = ok. (Именно эту цепочку дёргает виджет.)

### 3. 🔴 CORS + host-allowlist под фронт
- Разрешить origin PWA (прод-домен, напр. `https://malesthetic.pro`) и нативной
  оболочки (`capacitor://localhost` / схема приложения) — иначе фронт не сможет звать API.
- Дать Claude, как фронт получает tenant-boot на публичном домене: через
  `window.__ME_TENANT_BOOT` (инжект платформой в отдаваемый bundle) или
  `<meta name="me-tenant">`. Фронт уже это читает (fail-closed public-host логика).
  Нужно, чтобы отдаваемая на проде страница несла api base + tenant slug доверенно.

### 4. 🟡 Контракт «виджет в ответе чата» (для проактивной подачи)
- Сейчас виджет записи вызывается юзером по чипу «Записаться». Чтобы MAYA САМА
  присылала виджет по ходу разговора (дизайн-виженье: запись/магазин/подтверждение
  прямо в реплике), расширить ответ `POST /api/ai/chat`: опциональное поле
  `widget: { type: 'booking' | 'shop' | 'appointment' | ..., params?: {...} }`.
- Правила безопасности ядра не ослаблять; это чисто presentation-сигнал, факты
  по-прежнему из tool_results. Полный триггер-мэп (когда какой виджет) — в
  `MAYA_WIDGET_LIFECYCLE_MAP.md`. Фронт отрисует по типу.

### 5. 🟡 Проактивные события (следующий шаг, не блокер телефона)
- Для напоминаний/отзыва/чаевых/кэшбэка — события из `MAYA_WIDGET_LIFECYCLE_MAP.md`
  (шедулер `−24ч/−2ч`, `appointment→completed`, начисление оплаты), доставка через
  push, уважая `notify_prefs`. Можно позже.
