### 14. 🟡 Серверное удаление сообщений чата по контенту (не только по id)
- Проблема: `?action=chat_delete` с `delete_mode:'one'` удаляет по `message_id`. Но сообщения,
  созданные на клиенте, серверного `id` НЕ имеют → удаление по id промахивается → сообщение
  остаётся на сервере → при следующей подгрузке `chat_history` (в т.ч. на ДРУГОМ устройстве)
  «воскресает». Из-за этого удаление визуально срабатывало лишь со 2-го раза.
- Фронт-обход уже сделан (Claude): помеченные удалёнными сигнатуры (role+text/id) хранятся на
  устройстве и фильтруются из любой подгрузки истории — на ЭТОМ устройстве держится твёрдо.
  Но это device-local; авторитетное и кросс-девайс удаление — за бэком.
- Прошу от Codex:
  1. В `chat_delete` (`delete_mode:'one'`): если `message_id` отсутствует/не сматчился —
     удалять по контенту из тела запроса (`role` + `text`, уже присылаются; при неоднозначности —
     самое свежее совпадение). Вернуть обновлённый `messages[]`.
  2. Чтобы дальше было надёжно: пусть КАЖДОЕ сообщение в ответах `chat` / `chat_stream` (done) и
     `chat_history` несёт стабильный серверный `id` — тогда фронт удаляет по id без эвристик.
- Оплаты/прочего не касается. Приоритет 🟡 (UX уже держится на фронте, но кросс-девайс и «чистое»
  удаление — здесь).
