# CLAUDE_TIPS_WIDGET_RESULTS

## Что это

Backend-часть пункта 15 из `CLAUDE_TASKS_FOR_CODEX.md` закрыта. Легаси-чат «Мужской Эстетики» теперь умеет возвращать карточку чаевых по естественной просьбе клиента и проактивно после фактического завершения визита.

Backend уже развернут на production. Коммит: `a7917d5e`.

## Задача Claude

Backend не менять и не дублировать. Нужно только подключить готовый `ATipsCard` к новому контракту:

1. Рендерить `ATipsCard`, если сообщение чата или SSE `done` содержит `widget: "tips"`.
2. В проактивном сообщении прочитать `widget_data.master_id` и предвыбрать этого мастера.
3. Если есть `widget_data.base_amount`, показать варианты `10%`, `15%`, `20%`, рассчитанные от суммы визита. Оставить ввод своей суммы.
4. Если `widget_data` отсутствует, оставить текущий ручной выбор мастера и фиксированные пресеты. Это нормальный fallback для карточки, открытой самой MAYA из обычного диалога.
5. При вызове существующего `POST /api/tips/sent` передавать необязательное поле `note`. Максимум на backend - 240 символов.

## Контракт чата

Пример проактивного сообщения в `chat_history`:

```json
{
  "id": "msg_...",
  "role": "bot",
  "text": "Визит завершён - Мужская стрижка на 2 800 ₽. Ваш мастер - Илья. Поблагодарить чаевыми?",
  "widget": "tips",
  "widget_data": {
    "master_id": 1461615,
    "base_amount": 2800
  }
}
```

`widget_data.base_amount` может отсутствовать, если CRM не вернула сумму. Backend разрешает в `widget_data` только `master_id` и `base_amount`; личные данные и лишние поля отбрасываются.

Тот же `widget: "tips"` и `widget_data` передаются в payload Web Push. Старая ссылка `?tips=<master_id>` сохранена для обратной совместимости.

Пример сигнала о переводе:

```json
{
  "master_id": 1461615,
  "amount": 420,
  "record_id": 123456,
  "note": "Спасибо за стрижку!"
}
```

Успешный ответ:

```json
{
  "ok": true,
  "telegram": true,
  "push_sent": 1,
  "note_saved": true
}
```

`tip_sent` остаётся служебным сигналом «я перевёл», а не банковским подтверждением. Реальный перевод по-прежнему идёт по СБП. Оплата услуг не добавлялась.

## Серверная логика

- Проактивная карточка создаётся только при фактическом переходе визита в статус «завершён».
- Услуги, сумма и мастер берутся из реальной записи YClients.
- Повторная отправка одной и той же карточки блокируется по `record_id`.
- `tips` стал девятым допустимым виджетом в AI tool `show_chat_widget`.
- Текст благодарности хранится в аналитике чаевых и приходит мастеру в Telegram-уведомлении.

4. Отправить чаевые с `note` и без `note`; оба варианта должны завершаться без ошибки.
