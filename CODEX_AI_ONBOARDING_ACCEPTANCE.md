# CODEX AI ONBOARDING ACCEPTANCE

Дата приемки: 2026-07-13. Ветка платформы: `codex/ai-onboarding-foundation`.

Этот документ дополняет отчеты Claude и фиксирует окончательное состояние после независимой backend/frontend-проверки Codex.

## Принято

- AI-онбординг встроен в существующий `app.html` и не требует отдельного сайта или админки.
- Владелец описывает бизнес обычным текстом, проверяет собранную карточку и выбирает внутренний календарь MAYA либо внешнюю CRM.
- Для внутреннего календаря создаются владелец, специалисты, услуги и недельный график; после необязательного логотипа открывается рабочий календарь.
- Для внешнего календаря CRM-коннектор открывается внутри MAYA. YClients и Altegio доступны, остальные провайдеры честно помечены как `скоро`.
- White label в этом потоке ограничен логотипом. Цвета, шрифты и отдельный конструктор не добавлялись.
- PWA, iOS web source и сгенерированная Capacitor-копия byte-identical.

## Усиление после аудита

- `ownerName` обязателен и в интерфейсе, и в backend DTO. Создать бизнес без имени нельзя.
- Поле произвольного CRM Base URL удалено из tenant UI. Tenant admin получает `403`, если пытается передать `baseUrl`; менять системный endpoint может только platform owner.
- При смене CRM-провайдера обязателен новый API-токен. Зашифрованный токен предыдущего провайдера не переиспользуется.
- CRM API-токен остается только в памяти формы, передается на локально настроенный backend и хранится сервером в зашифрованном виде.
- CRM-подключение не включает live-запись: новый tenant остается в `booking_mode=preview`.
- Исправлен external-server guard HTTP smoke runner, чтобы он мог проверять уже поднятый изолированный backend.

## Проверено

- `npm run lint`.
- `npm test -- --runInBand`: 46 suites, 200 tests.
- `npm run build`, `npm run typecheck`, `npm run typecheck:scripts`.
- `npm run test:http`: AI onboarding, tenant isolation, auth rotation, CRM preview и internal calendar booking.
- 67 inline-скриптов PWA/admin/iOS разобраны через `new Function(...)`.
- Browser E2E internal: рассказ о бизнесе -> обязательное имя -> создание tenant -> логотип/пропустить -> готовые услуги и график в календаре MAYA.
- Browser E2E external: рассказ о бизнесе -> in-app CRM -> подключить позже -> preview нового tenant.
- API negative paths: tenant Base URL override -> `403`; смена provider без нового token -> ошибка; безопасное обновление без Base URL -> успешно.

Проверки выполнялись на портах `3102/8889` и в отдельной PostgreSQL-базе. После приемки процессы остановлены, временная база удалена. Production и основные локальные процессы не изменялись.

## Осознанные ограничения

- Настоящие YClients/Altegio не проверялись без пользовательских токенов. До явного включения конкретного tenant запись остается в preview.
- DIKIDI, Salon Online и Whitelines пока имеют backend-заглушки и поэтому недоступны для выбора.
- Голосовой ввод переиспользует существующий STT-прокси MAYA; полностью локальный backend гарантированно поддерживает текстовый сценарий.
- Текущий безопасный интерпретатор детерминированный: он распознает структурированные факты, но еще не является свободным LLM-диалогом для любых формулировок.
