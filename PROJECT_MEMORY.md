## 1. Текущая архитектура (кратко)

Барбершоп-ассистент: **Telegram-бот «Антон»** + **PWA** поверх **YClients** как источника правды. Бэкенд (Python, VPS `111.88.148.206`) = бот `bot.py` + webhook/REST-сервер `webhook_server.py:8080`, общий слой данных `database.py` (SQLite — надстройка, не источник правды). Фронт (Beget) = `index.html` (сайт) + `app.html` (PWA, React/Aurora), все запросы через PHP-прокси `api-proxy.php`. Внешние сервисы: Claude (через прокси из-за геоблока РФ), OpenAI gpt-5.1, fal.ai, YooKassa, Web Push, VK ID. Полная карта — в [ARCHITECTURE.md](ARCHITECTURE.md).

Параллельно ведётся **SaaS-переписка** (`saas_blueprint/`) — мультитенант на PostgreSQL, ещё не в проде.

## 2. Реализованные функции

**Запись и YClients**
- AI-запись/перенос/отмена через диалог с «Антоном» (Telegram и PWA-чат — один мозг).
- Мультиуслуга за визит; пересчёт `seance_length` при изменении набора услуг.
- Журнал мастера в PWA: create/reschedule/cancel/attendance/pay/add_service/set_services/set_client_name.
- Закрытие визита нал/карта → транзакция в кассу YClients.
- Оффер освободившегося слота (webhook `record.delete`) + лист ожидания (`slot_waitlist`).

**Удержание и лояльность**
- Программа лояльности: 5% кэшбэк, 1 балл=1₽, тратится только на уходы (`CARE_SERVICES`), сгорание 12 мес, коды `LOY-XXXXXX`.
- Рефералы `REF-XXXXXX`: 2 промокода −15%/30дн после первого посещённого визита друга, антифрод.
- Абонементы: 3 продукта × 2 тарифа (senior/top, 3300–6000₽), оплата ЮKassa, списание по факту посещения.
- Подарочные сертификаты: PDF-генерация (`cert_pdf.py` + `cert_assets/`), оплата ЮKassa, погашение по коду `MEC-` / QR админом.
- Поздравления с ДР (−20%), реактивация уснувших (4–8 нед), предсказательное напоминание по циклу визитов.

**ИИ**
- «Антон» (Claude Sonnet 4.5, 20 tools, prompt caching).
- AI-апсейл-советы мастерам при новой записи (Claude Haiku 4.5 / GPT-4o-mini).
- **CutMatch** AI-стилист: анализ лица (gpt-5.1 + Claude-фолбэк) и примерка причёски (fal.ai), лимит 2/день.
- Учёт расхода токенов и бюджет (`/ai_cost`, `/stats_ai`).

**Маркетинг и владелец**
- Отзывы после визита (4–5★ → Яндекс/2ГИС, 1–3★ → алерт админам).
- Рассылки по шаблонам (`/broadcast`), лид-алерты о зависших заявках.
- Дневной отчёт владельцу (21:00): ЗП барберов, нал/карта; учёт расхода `/rashod`.
- Founder GOD-режим: `/dashboard`, `god_watch`, `/api/god/*` в PWA.
- Атрибуция источников клиентов (QR/UTM в `/start`).

**PWA-специфика**
- Веб-вход: Telegram Mini App (initData HMAC) + Login Widget; телефон (SMS.ru) и VK ID — код есть, **выключены конфигом**.
- Чаевые: `tips.html` + QR-наклейки, уведомление мастеру «Я перевёл».
- Web Push мастерам/владельцу (VAPID).
- «Настроение визита» (red/blue пилюли).

## 4. Бизнес-логика (ключевые правила)

- **Лояльность:** кэшбэк 5% от суммы услуг после скидок; НЕ начисляем за визиты, полностью покрытые абонементом; UNIQUE-индекс `(client_id, visit_record_id, type='earn')` от двойного начисления; баллами за визит можно оплатить только ОДНУ услугу-уход (backend оставляет самую дорогую по балансу).
- **Рефералы:** промокоды выдаются только при `attendance=1` приведённого друга ПОСЛЕ `joined_at`; нельзя пригласить себя.
- **Абонементы:** визиты списываются по факту `attendance=1` в окне `started_at..expires_at`, не при бронировании.
- **Запись:** на любое время — только админский путь `records/{company}`; клиентский `book_record` отклоняет нерабочее время (422). PWA-журнал использует админский путь.
- **Перенос:** только неразрушающий `PUT` (никогда delete+create).
- **`request_booking` обязан идти ПОСЛЕ `suggest_upsell`** — иначе backend блокирует (⛔) и заставляет повторить.
- **Финансы:** нал vs карта определяется по `account.is_cash` транзакции YClients (не по тому, какой `account_id` записали). ЗП = выручка по услугам × процент (по умолчанию 50%, Илья `#1460233` 60%, владелец `#1461615` 100% не выплачивается).
- **152-ФЗ:** ПД (имя/телефон/email/id) НИКОГДА не передаются в LLM; собираются отдельным детерминированным backend-шагом; шифруются Fernet at rest; `phone_hash`=HMAC для поиска; обезличивание через 18 мес; отдельное согласие на трансграничную передачу фото в AI.
- **Источник клиента** фиксируется по first-touch (первый `/start`), дальше не меняется.

## 5. БЕЗОПАСНОСТЬ — 🔴 КРИТИЧЕСКИЙ УРОВЕНЬ

> Все находки ниже подтверждены чтением реальных файлов (адверсариальная верификация). **Конкретные значения секретов в этот файл сознательно не вынесены.** Проект **не под git** и без `.gitignore` — единственный защитный слой отсутствует.

**Критично — считать скомпрометированным, ротировать немедленно:**
1. `ai администратор/config.py` — узловой файл: Telegram BOT_TOKEN, Claude (`sk-ant-`), OpenAI (`sk-proj-`), YClients partner+user токены, VK secure key, **YooKassa LIVE secret (`live_`) — реальные деньги**, WEBHOOK_SECRET и **`PII_ENCRYPTION_KEY` (Fernet) — расшифровывает все ПД клиентов**.
2. `ai администратор/bot.log` — полный Telegram BOT_TOKEN протекает **985 раз** (python-telegram-bot логирует URL с токеном).
3. `smm_bot/config.py` — отдельные BOT_TOKEN/VK/Publer + **переиспользованные те же** Claude/OpenAI ключи (одна утечка бьёт по двум приложениям).
4. `сайт и приложение/pwa-assets/tg-auth/api-proxy.php.bak.sesstoken` — в веб-руте Beget, расширение `.sesstoken` ⇒ **НЕ исполняется как PHP и НЕ покрыто `.htaccess`** ⇒ при выкладке отдаётся как plaintext-исходник с YClients PARTNER_TOKEN.
5. `МЭП - Google Play package/` — **пароль keystore лежит рядом открытым текстом** в `signing-key-info.txt`, а `secret_key.txt` содержит live-секрет YooKassa. Keystore (×2 копии) — единственный ключ подписи приложения в Google Play.

**Высокий риск:**
- `vapid_private.pem` — две байт-идентичные копии (одна `0644` в веб-ассетах PWA; в бэкенде `0600`).
- BOT_TOKEN/PARTNER_TOKEN зашиты в `tg-config.php` и `api-proxy.php` прямо в веб-руте (защита только `.htaccess` по имени).
- `signing.keystore` — 2 копии в дереве.

**Средне/низко:**
- `barbershop.db` — со схемой ПД (но локальная копия **пустая**; реальные ПД только на VPS); в `clients` одновременно есть и plaintext-колонки `name/phone`, и `*_enc` (design smell).
- `CRM/config.php` — live `API_TOKEN`, но `DB_PASS` ещё плейсхолдер; `CRM/index.html` — `API_TOKEN` захардкожен в клиентском JS (токен-защита обходится).
- `web_auth.py.bak.yclientsms` — без зашитых ключей; лежит в **бэкенд-папке** (не веб-рут), напрямую по HTTP не отдаётся.

**План санации** — см. [ROADMAP.md](ROADMAP.md) §«Безопасность».

## 6. Известные проблемы

- **Промокоды применяются вручную:** клиент называет код мастеру, мастер ставит скидку в YClients руками — нет программного применения, риск рассинхрона.
- **Веб-вход телефон/VK выключены** (`SMSRU_API_ID` пуст, `VK_LOGIN_ENABLED=False`) — единственный реальный вход PWA = Telegram initData.
- **`handle_callback`** — единый мега-роутер по ~20 префиксам; pattern в `add_handler` надо синхронизировать вручную при добавлении префикса (хрупко).
- **`barbershop.db` локально пустая** — риск тестировать на пустой базе и пропустить регрессии.
- **Claude геоблокирует РФ** — все вызовы через `PROXY_URL`; упал прокси ⇒ «Антон» молчит.
- **Защита от двойной оплаты — in-memory `_pay_locks`** — работает только в одном процессе; при горизонтальном масштабировании двойная касса вернётся.
- **`_check_booking_fits`** проверяет влезание услуг по локальному `schedule.json`, а не по живому графику YClients — рассинхрон ⇒ ложные блокировки.
- **Расхождения документации:** скилл деплоя ссылается на отсутствующие `app-aurora.html`/`build.js`; `cutmatch.py` docstring (gpt-4o/nano-banana) расходится с кодом (gpt-5.1/gpt-image); `demo/landing.html`,`scrub.html` под старым брендом «Aura».
- **SaaS:** локальная Postgres-репетиция и `.sandbox_secret.key` отсутствуют ⇒ «~98 зелёных тестов» сейчас невоспроизводимы (проходит только `test_plan_catalog.py` 36/36); `YooKassaGateway.charge` — заглушка `NotImplementedError`.
- **CRM** — `DB_PASS` не заполнен; повторный импорт `database.sql` сотрёт данные.

## 7. Технический долг

- **Монолиты:** `bot.py` (6404 стр), `webhook_server.py` (6546 стр), `database.py` (3316 стр) — нужна декомпозиция по доменам. Каждый `/api/*` вручную регистрирует `add_post`+`add_options` (легко забыть CORS-preflight).
- **Секреты в коде** вместо env/секрет-стора (см. §5).
- **Нет git** ⇒ нет версионирования 300КБ-монолитов, откат только через `.bak`.
- **Ad-hoc миграции** (`ALTER TABLE` в try/except), без alembic-подобного версионирования.
- **Бизнес-константы размазаны** по модулям и `config.py` — нет единого каталога продуктов/цен.
- **Хардкод** `expense_id=5`, `OWNER_STAFF_ID`, `MASTER_SALARY_PCT`, кассы, `company_id`, IP бэкенда.
- **Цены моделей ИИ** (`ai_billing.MODEL_PRICES`) обновляются вручную — разъедутся при смене тарифов.
- **Дублирование:** нормализация телефона в 3 местах; иконки for-app↔for-root; Google Play пакет в 3 местах; два SW с похожими именами.
- **SaaS — двойное сопровождение:** `db_pg_full.py` (147 КБ) авто-генерится из `database.py`; правки нужно вносить в оба до катовера. Хардкод абсолютных путей разработчика.
