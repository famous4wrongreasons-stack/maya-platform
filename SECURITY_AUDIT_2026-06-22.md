### [CRITICAL] AuthN · БОТ/web_auth.py
**VK SDK auth: client-controlled user_id не верифицируется против access_token → подмена аккаунта и эскалация до staff**

- 📍 `web_auth.py:190-211 vk_session_from_token (через /api/auth/vk-sdk, webhook_server.py:5669-5680)`
- Описание: Эндпоинт /api/auth/vk-sdk принимает {access_token, user_id} прямо из тела запроса. В vk_session_from_token vk_user_id берётся из клиентского ввода (int(vk_user_id)) и используется как identity сессии. access_token уходит только в VK user_info для получения имени/телефона, но НИКАК не сверяется с присланным user_id: при ошибке/исключении user_info (или просто при несовпадении) код продолжает и всё равно вызывает issue_vk_session(vk_user_id,...). То есть сервер доверяет user_id, который не привязан криптографически к проверенному токену. В _issue_session (web_auth.py:230-234) этот vk_user_id матчится по config.VK_STAFF_CHAT_MAP → chat_id сотрудника, и затем database.is_admin(chat_id) выставляет subject_kind='staff'. Сейчас VK_STAFF_CHAT_MAP пуст (в config.py его нет), но как только владелец его заполнит (это и есть заявленный сценарий «владелец заходит через ВК без VPN»), путь становится боевым.
- Impact: Аутентификация без владения аккаунтом: атакующий шлёт произвольный user_id и (любой/пустой) access_token и получает валидную 30-дневную веб-сессию от имени этого VK-пользователя — доступ к чужому кабинету, ПДн, баллам, истории. При заполненном VK_STAFF_CHAT_MAP — прямая эскалация до staff/админ-панели (impersonation владельца/мастера) подбором известного staff VK-id. Полный обход аутентификации.
- 🔧 Фикс: Никогда не доверять user_id из тела. Получать user_id ТОЛЬКО из результата серверной валидации токена: вызвать VK user_info, и если запрос упал/не вернул user — отказать (return error), а не выдавать сессию. Сверять id из ответа VK с присланным user_id и при несовпадении отклонять. В идеале не принимать access_token от клиента вовсе, а завершать OAuth-обмен на сервере (как в exchange_vk_code с PKCE) и брать user_id из обмена. Сделать user_info обязательным шагом, а не try/except-обёрткой, после которой выдаётся сессия.
- Перепроверка: Подтверждено по коду. Эндпоинт POST /api/auth/vk-sdk зарегистрирован в проде (webhook_server.py:6858) и принимает {access_token, user_id} прямо из тела (5678-5679 → body.get("user_id")).
