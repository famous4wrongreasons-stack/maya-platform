# Журнал стабилизации MAYA

## Цикл 0 — карта системы (2026-08-15)

**Cycle:** 0 — построить карту исполнения CRM-запроса, код не менять.

**Problem:** Заявлено, что MAYA отвечает «нет доступа» / «нет инструмента» из-за
внутренних архитектурных противоречий: нескольких реестров, нескольких движков
прав, нескольких адаптеров.

**Root cause:** Не подтверждено. Проверка показала обратное: реестр один
(`MAYA_AI_TOOL_CATALOG`, 49 инструментов), движок прав один
(`AiToolPolicyService`), путь к YClients один (`CrmAdapterFactory` →
`YclientsCRMAdapter`), ошибки CRM уже типизированы кодами `crm_*`. Восемь из
требований раздела «критерии готовности» выполняются на текущем HEAD.

Настоящие расхождения — другие, их шесть, они перечислены в
[MAYA_CRM_EXECUTION_MAP.md](MAYA_CRM_EXECUTION_MAP.md), раздел «Что расходится
с требованиями». Наиболее вероятная причина отказов — не дубли, а
`closedForAccess` (`ai-core.service.ts:1784`), который закрывает денежный вопрос,
когда у арендатора нет фичи `analytics.business`. Это честный отказ по тарифу,
но пользователю он читается как «нет доступа».
