# Maya booking handoff — 2026-10-22

## Current scope

The owner requires a real AI conversation for their own appointment creation,
rescheduling and cancellation. A phrase matcher opening a booking panel is not
an accepted substitute. The owner chooses and confirms real actions.

## Current source

- `maya-carrier-react/`: installed React/Capacitor presentation.
- `maya-chat-shell/`: shared conversation runtime, transport and projections.
- `maya-saas-backend/`: NestJS, PostgreSQL, YCLIENTS and canonical action owners.
- `maya-ios-carrier/`: native carrier of the same React payload.

This branch includes the current own-booking HTTP implementation and the removal
of the rejected automatic phrase-to-panel interception. It is not a claim that
live conversational AI booking is complete. Additional owner-personal AI policy
and inline approval work is in progress and is not included in this snapshot.

## Implemented ordinary own booking

Authenticated personal-client preview/create and own appointment list/cancel/
reschedule reuse existing verified Client and Action Engine owners. Business
membership roles are preserved. YCLIENTS moves use PUT rather than delete/create.
The deterministic booking contact is read from the exact preverified CRM card;
no whole client registry is fetched for it. Current synthetic targeted HTTP and
UI checks do not replace real owner acceptance.

## Remaining conversational work

Connect the actual model within the owner's approved total test budget; support
personal booking for an authenticated business owner through the verified Client
context; preserve live permissions, exact proposal binding, explicit approval,
idempotency and UNKNOWN handling. Render confirmation inline in the chat.
Do not grant Client roles, bypass authorization, fabricate widget certificates,
or report successful booking before a canonical execution receipt.

## Secrets and environment

This public Git repository intentionally contains no credential bundle.
Supply credentials only through the destination runtime's protected secret store.
Use `.env.example` and the runtime configuration source for actual variable names.
Relevant categories include PostgreSQL credentials, JWT and CRM encryption keys,
YCLIENTS partner credentials, model-provider keys, and Telegram bot/webhook secrets.
The salon's YCLIENTS user token is stored encrypted in its existing CRM integration.
Existing encryption keys and database must remain paired. Never replace them or
copy real customer contacts into an LLM prompt, repository, ticket or chat.

## Operational boundaries

Preserve the installed phone's data, database, keys and owner worktree changes.
Do not deploy the historical website instead of the active carrier. No database
reset, automatic real booking/cancellation, OTP or real message broadcasts.
Model testing and owner dialogue share one total approved $2 budget; do not
silently create a second budget. No new broad test programme or CI reruns for
this handoff snapshot.
