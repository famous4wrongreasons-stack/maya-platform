# Native Staff Schedule Chat Commands

## Статус И Область

Команды управления графиком являются ограниченным native-only сценарием Maya
OS. Они доступны в нативном приложении и не меняют production PWA. Источником
архитектурных правил является спецификация Maya OS из PR #21.

Первая версия поддерживает три действия на один день одного мастера:

- закрыть день полностью;
- поставить один перерыв внутри текущей смены;
- сократить рабочий день, изменив время окончания смены.

Примеры пользовательских формулировок:

- `Закрой <имя мастера> завтра`;
- `Поставь <имя мастера> завтра перерыв с 14:00 до 15:00`;
- `<имя мастера> завтра работает только до 18:00`.

Maya понимает относительные даты, дни недели, даты `DD.MM`, ISO-даты и даты с
русским названием месяца. Если дата, мастер или время определены неоднозначно,
Maya задаёт уточняющий вопрос и ничего не изменяет.

## Доступ

Tool `staff.schedule.update` разрешён только на поверхности `native` ролям:

- `tenant_owner`;
- `business_owner`;
- `tenant_admin`;
- `administrator`;
- `manager`;
- `branch_manager`.

Дополнительно проверяется entitlement `booking`. Tenant берётся только из
аутентифицированного серверного контекста. Клиент, модель и тело запроса не
могут выбрать или подменить tenant.

## Контракт Tool

| Свойство | Значение |
|---|---|
| Имя | `staff.schedule.update` |
| Surface | `native` |
| Risk tier | `medium_write` |
| Approval | подтверждение инициатора (`actor`) |
| Idempotency | обязательна |
| Retry | отсутствует |
| Failure policy | `fail_closed` |

Неизменяемый payload подтверждения содержит:

- `staff_id`;
- `date`;
- `operation`: `close_day`, `set_break` или `set_hours`;
- `current_revision`;
- `current_slots`;
- `slots` после изменения.

Аргументы шифруются, связываются с actor, surface и payload hash. Повторное
использование idempotency key с другим payload отклоняется.

## Поток Выполнения

1. Детерминированный parser проверяет команду до обращения к LLM и работает
   только при `surface=native`.
2. Backend проверяет роль, tenant, entitlement и доступность tool.
3. Имя мастера сопоставляется локально со списком сотрудников tenant. Исходное
   имя не отправляется модели.
4. Через CRM adapter читается точный текущий график мастера на выбранную дату.
5. Backend детерминированно рассчитывает новые интервалы.
6. Выполняется preview: все будущие записи должны целиком помещаться в новый
   график.
7. Пользователь видит текущий и новый график и подтверждает точный payload.
8. Перед записью backend повторно проверяет роль, entitlement, revision и
   конфликты.
9. YClients получает точное изменение графика через
   `PUT company/{company}/staff/schedule`.
10. Результат перечитывается и сверяется. При несовпадении backend пытается
    восстановить прежний график и завершает операцию ошибкой.

Существующие записи не удаляются, не переносятся и не создаются заново. Если
хотя бы одна запись не помещается в новый график, операция отклоняется до
подтверждения без каких-либо изменений в CRM.

## Пользовательский Контракт

Перед изменением карточка подтверждения показывает:

- мастера и дату;
- тип операции;
- текущие рабочие интервалы;
- предлагаемые интервалы;
- явное подтверждение, что существующие записи сохраняются.

После успешного подтверждения приложение показывает `График обновлён.`. При
ошибке чтения, preview, конфликте, устаревшей revision или недоступном CRM Maya
сообщает, что ничего не изменила. Догадки и частичное выполнение запрещены.

## CRM И Ограничения Пилота

В текущем пилоте write-операция реализована для внешнего YClients adapter.
Adapter без методов чтения, preview и применения графика отклоняет запрос.

В первую версию не входят:

- массовое изменение графиков;
- повторяющиеся смены и перерывы;
- перенос или отмена конфликтующих записей;
- создание смены с нуля без существующего рабочего интервала;
- production PWA, Telegram и voice surfaces.

## Feature Switch И Откат

Переключатель:

```env
MAYA_NATIVE_SCHEDULE_ACTIONS_ENABLED="true"
```

Значение `false` полностью отключает parser и tool-сценарий после перезапуска
backend. В текущей реализации отсутствие переменной не отключает функцию,
поэтому для аварийной остановки необходимо явно установить `false`.

Порядок быстрого отката:

1. Установить `MAYA_NATIVE_SCHEDULE_ACTIONS_ENABLED="false"` и перезапустить
   `maya-saas.service`.
2. Если требуется откат кода, переключить `/opt/maya-saas/current` на
   предыдущий проверенный release и снова перезапустить service.
3. Проверить `/api/health`, отсутствие незавершённых migrations и aggregate
   audit/approval counts без просмотра зашифрованных payload.

## Проверка Перед Релизом

- parser tests для всех трёх операций, уточнений и web bypass;
- registry/runtime tests для role, surface, schema, approval и idempotency;
- CRM adapter tests для payload YClients, конфликтов и проверки результата;
- полный backend test suite;
- `release:preflight` и проверка migrations;
- native build содержит маркеры `staff.schedule.update` и
  `График обновлён.`;
- production PWA не имеет изменений от этого релиза.
