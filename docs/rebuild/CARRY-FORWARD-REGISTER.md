## Долг тестирования

### Спеки вне проверки типов

| | |
|---|---|
| Причина | `npm run typecheck` идёт по `tsconfig.build.json`, где `**/*spec.ts` исключены |
| Масштаб | `tsc -p tsconfig.json` → **221 ошибка в 32 спек-файлах**, **0** в боевом коде |
| Самое опасное | 23 ошибки арности: сервис в тесте строится без части зависимостей и молча получает `undefined` |
| Уже проявилось | `customers.service.spec.ts` строил сервис 5 аргументами при 6 — тест списка клиентов закреплял обход границы лояльности как норму. В P7.1 исправлен |
| Осталось | пять спек с той же болезнью: `crm.service.spec.ts`, `crm.visit-operations.spec.ts`, `adversarial-expense-audit.spec.ts`, `ai-tool-expenses-create.spec.ts`, `owner-money-questions.acceptance.spec.ts` |

**Правило до починки целиком** (соблюдено в P7.1): любая спека, которую трогает
пакет, должна быть типизирована корректно и не закреплять старый обход.

**Целевой пакет: отдельный, вне главы 3.**

### Чего у тестов нет

| Пробел | Следствие |
|---|---|
| Интеграционного контура нет: ни фикстур, ни второго jest-проекта с Postgres | Всё держится на моках; поведение БД (внешние ключи, каскады, уникальности) проверяется только вручную, как в P7 |
| Барьерный тест границы узок | Охраняет импорты одного файла и одно написание идентификатора; форму данных и остальные модули `src/crm` не охраняет |
| Доменный тест лояльности узок | Проверяет значения перечисления и коды предупреждений, а не файл целиком |
