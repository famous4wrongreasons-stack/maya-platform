## Образец восстановительной миграции

Ваше требование «обнаруживать, а не прятать» принято — и оно делает моё прежнее
предложение с `IF NOT EXISTS` **непригодным**. `IF NOT EXISTS` молча проходит
мимо объекта, который существует, но отличается типом, обнуляемостью или
значением по умолчанию. Это ровно тот случай, ради которого цикл и затеян.

### Правильный образец: создать, либо сверить, либо упасть

Для каждого объекта — три исхода вместо двух.

**Колонка:**

```sql
DO $$
DECLARE actual RECORD;
BEGIN
  SELECT data_type, is_nullable, coalesce(column_default, '') AS column_default
    INTO actual
    FROM information_schema.columns
   WHERE table_schema = current_schema()
     AND table_name  = 'MarketingCampaign'
     AND column_name = 'scheduledFor';

  IF NOT FOUND THEN
    -- Чистая база: создаём.
    ALTER TABLE "MarketingCampaign" ADD COLUMN "scheduledFor" TIMESTAMP(3);

  ELSIF actual.data_type      <> 'timestamp without time zone'
     OR actual.is_nullable    <> 'YES'
     OR actual.column_default <> '' THEN
    -- Прод отличается от ожидаемого: НЕ пропускаем молча.
    RAISE EXCEPTION
      'reconciliation mismatch: MarketingCampaign.scheduledFor is type=%, nullable=%, default=%',
      actual.data_type, actual.is_nullable,
      nullif(actual.column_default, '');
  END IF;
  -- Совпало — ни одной операции.
END $$;
```

**Таблица:** `to_regclass` вместо `IF NOT EXISTS`; если таблица есть, сверяется
полный набор колонок, и любое расхождение поднимает исключение.

**Ограничение и индекс:** поиск по `pg_constraint` / `pg_indexes` и сравнение
**полного определения** через `pg_get_constraintdef` и `indexdef` — не только
имени. Одинаковое имя при разном определении обязано падать.

### Что это даёт

| Где | Поведение |
|---|---|
| Прод, структура совпадает | Ноль операций DDL, добавляется одна строка в `_prisma_migrations` |
| Прод, структура отличается | **Миграция падает** с точным указанием объекта и различия. Выкат откатывается штатно |
| Чистая база | Создаётся всё недостающее, структура совпадает с продом |

Данные не удаляются, существующая семантика не меняется, `IF NOT EXISTS` как
способ спрятать несовпадение не используется нигде.

### Как это будет написано

Ста с лишним блоков вручную не будет: они **генерируются** из снятых срезов —
для каждой недостающей строки эталонного диффа свой блок с подставленными
фактическими типом, обнуляемостью и значением по умолчанию, взятыми **из
прода**. Поэтому шаг «снять структуру прода» обязателен и не заменяется
догадками.

### История миграций

Старые строки `_prisma_migrations` не переписываются и не удаляются. Дубликат
`20260814210000_outbound_messaging_delivery` с двумя разными контрольными
суммами остаётся как **историческая аномалия** и фиксируется, а не чинится.
Новая миграция — отдельная новая точка отсчёта.
