## Architecture Invariants

Каждый пункт перепроверен заново.

| Инвариант | Чем доказан |
|---|---|
| Приём аутентифицирован | `sha256` + `timingSafeEqual`, отказ при секрете короче 24 символов |
| Арендатор — из стабильной связи, не из слага | `resolveByIntegration` первым; у теневого DTO **поля слага нет вовсе** |
| Непонятое не теряется | четыре причины карантина: `tenant_unresolved`, `unknown_discriminator`, `malformed`, `source_unreadable` |
| Тело доставки не является доказательством | из тела берутся только маршрутизация и различитель; состояние **перечитывается** у источника — устаревший вебхук невозможен по построению |
| В диагностике нет ПД | только имена ключей и неперсональные скаляры; мост из легаси шлёт то же самое |
| Изоляция арендатора | `assertTenantId` бросает `Cross-tenant access is not allowed` при несовпадении контекста |
| Дедупликация в БАЗЕ, не в памяти | вставка того же отпечатка **из другого процесса** отвергнута: `DomainEvent_tenantId_dedupFingerprint_key` |
| Ключ дедупликации ограничен арендатором | тот же отпечаток у другого арендатора **принят** |
| Приём отделён от обработки | `occurredAt` / `receivedAt` / `processedAt` — три разные колонки; `status`, `attempts`, `leaseUntil` |
| Повтор — не ошибка | исход `duplicate`, а не исключение |
| Карантин отделён от событий | отдельная таблица без типа и сущности — прочитать как факт невозможно по построению |
| Визит существует без аккаунта Maya | **1928 из 1946** визитов с `clientId = NULL` |
| Аккаунт и клиент бизнеса — разные поля | `clientId` (аккаунт, `SetNull`) и `mayaClientId` (клиент, `Restrict`) |
| Идентичность визита квалифицирована провайдером | `@@unique([tenantId, crmProvider, crmExternalId])`, дубликатов идентичности **0** |
| Мастер — идентичность Maya | 1932 из 1946 с `staffId`; оставшиеся 14 — два ушедших мастера, восстановление которых владелец запретил |
| Наполнение не создало истории | событий с `ingestionMethod='bootstrap'` — **0** |
| Зеркало сходится | последние три прогона: `updated=0`, `unchanged=152` |

## Event Vocabulary

Версия контракта — **1**, номер живёт в колонке, не в имени.

| Тип | Доказуемость из канонического состояния | Нагрузка |
|---|---|---|
| `appointment.created` | записи не было в зеркале **и** базовая линия установлена | `start_at`, `end_at`, `staff_external_id`, `staff_id`, `service_ids` |
| `appointment.removed` | статус стал снятым | `previous_status` |
| `appointment.rescheduled` | изменилось `startAt` и/или `endAt` | `from{start_at,end_at}`, `to{…}` |
| `appointment.staff_changed` | изменился мастер | `from_staff_external_id`, `to_…`, `from_staff_id`, `to_…` |
| `appointment.services_changed` | изменился отсортированный состав | `from[]`, `to[]` |
| `appointment.attendance_changed` | переход между двумя **доказанными** значениями | `from`, `to` |

- Все шесть объявленных типов **реально выпускаются** компаратором — сверено
  перечислением обращений к словарю.
- Провайдерских слов в словаре — **0**: ни `record`, ни `resource`, ни имени CRM.
- Отпечаток детерминирован: без времени, без провенанса, с устойчивым порядком
  ключей и сортировкой массивов; способ приёма на него **не влияет**.
- Порядок переходов — часть контракта: `removed` поглощает остальные, далее
  `rescheduled → staff_changed → services_changed → attendance_changed`.

🔴 **Историческая строка.** В базе есть одно событие типа
`appointment.attendance_recorded` — проба B2 до переименования. Тип из словаря
удалён, строка оставлена сознательно как след. Потребитель, читающий словарь,
этого типа не найдёт — это известно и принято.

## Reconciliation Guarantees

| Гарантия | Доказательство |
|---|---|
| Контракт полноты B3.0 | `FetchResult.completeness`, `allowsAbsenceInference` разрешает выводы только при `complete` |
| Усечённое ≠ пустое | усечённая выборка несёт элементы **и** признак усечения |
| Сбой провайдера ≠ «записей нет» | в `fetchRecords` **нет** `catch`: ошибка летит наружу, пустым списком не притворяется |
| Неполный прогон не заключает отсутствие | `removed` выпускается только по доказанному признаку у самой записи, никогда по отсутствию в выборке |
| Устойчивый single-flight | частичный уникальный индекс; два процесса в бою: один `ran`, второй `already_running` |
| Истёкшая аренда восстанавливается сама | брошенный прогон закрывается как `lease_expired` со следом, ручной разблокировки не требуется |
| Ручной запуск — та же аренда | обходного пути нет; занято → честный `already_running` |
| Ритм | ближний контур: **28, затем 30 минут ×17** подряд |
| Только активные интеграции | `maya-os` без CRM: **0 прогонов**; салон: 25 |
| Изоляция сбоя арендатора | `try` вокруг каждого арендатора, не вокруг цикла |

### 🔴 Ограничение, которое нельзя замалчивать

**Провайдер возвращает записи ВНЕ запрошенного окна.** Измерено: прогон с окном
`2026-07-17 … 2026-09-17` тронул 499 строк, из них **17 датированы 2024–2025
годами**.

Поэтому «прочитано N за окно» **не означает** «в окне N записей», и полнота окна
не заявляется сильнее, чем доказана: `complete` означает «выборка не была
усечена постраничным потолком», а не «выборка равна окну».

Семантику адаптера сейчас не меняем. Правило «отсутствие нельзя выводить из
оконного чтения» остаётся обязательным — и теперь оно опирается на факт, а не на
осторожность.

## 🔴 Незакрытые места

### 1. Срок хранения карантина объявлен, но не применяется

`expiresAt` заполняется у каждой строки (по умолчанию 14 дней, настраивается,
потолок 90). **Удалять истёкшие строки некому**: во всём репозитории нет ни
одного `delete` по `IngestionQuarantine`.

Комментарий в схеме утверждает: «Это диагностика, а не история: она обязана
истекать». Сегодня она не истекает. В бою вреда ещё нет — самый ранний срок
`2026-08-31`, истёкших **0**, — но заявленное поведение не выполняется.

Сказать «retention policy присутствует» значило бы повторить ошибку, с которой
эта глава боролась: описать намерение как факт.

**Закрытие:** уборка истёкших строк — там же, где живёт остальная уборка, с
тестом «истёкшая строка удалена, живая осталась».

### 2. Неизвестный словарь доставок не занесён в реестр

Провайдер шлёт доставки, которых Maya не понимает. В бою их **6 открытых строк
четырёх видов**: `client/create`, `client/update`, `staff/update`,
`finances_operation/*`. Кассовые операции в реестре есть (4.0), остальные — нет
ни одной строкой.

Владелец прямо просил проверить этот пункт. Он отсутствует.

**Закрытие:** строка реестра «неизвестный словарь доставок провайдера» с
перечислением наблюдённых видов и правилом: не угадывать, а разбирать отдельно.

### 3. Число долга тестирования в реестре устарело

Значилось 221 ошибка в 32 файлах, фактически — **224 в 33**. В боевом коде
по-прежнему 0. Косметика, но реестр должен быть точным.
