## Часть I. Что сделано в B0 — без изменения схемы

### 1. Приём из бота перестал быть мёртвым

Было: слаг в окружении бота (`muzhskaya-estetika`) разошёлся с боевым
(`muzhskaya-estetika-3`), **каждый** вызов моста получал 403 — 37 отказов за
неделю, ноль карточек в Maya OS.

Чинилась причина, а не имя. Введён общий резолвер мостов
`tenancy/bridge-source.service.ts`:

```
(провайдер, идентификатор компании) → CrmIntegration → арендатор     ← истина
слаг                                                                 ← совместимость
```

Отображение живёт в данных (`settingsJson.companyId = 503759`), его владелец не
переименовывает, и граница CRM уже им пользуется.

**Доказательство на проде, без побочных эффектов** — тот же неверный слаг, но с
парой «провайдер + компания»:

| Запрос | Ответ |
|---|---|
| с парой, слаг `muzhskaya-estetika` (неверный) | **201**, `stored: 0` |
| без пары, тот же слаг | **403**, `inbox_tenant_not_found` |
| `InboxItem` до и после | **4 → 4**, строк пробы — 0 |

Пробный вызов подобран так, что получателей нет: разрешение арендатора
проверено, а карточка не создана.

### 2. Неоднозначность и догадки закрыты

- две интеграции на одну компанию провайдера → **отказ**, а не «первая
  попавшаяся»: доставить можно не тому салону;
- «в базе один салон — значит он и есть» → **нет**: арендаторов два;
- приостановленный арендатор мост не принимает.

### 3. Секрет мостов сравнивается одним способом

`inbox` сравнивал строки через `!==`, `recovery` — `timingSafeEqual`, **секрет
один и тот же**. Теперь один метод на оба входа, сравниваются свёртки: на голых
строках `timingSafeEqual` требует равной длины, и разная длина сама стала бы
утечкой.

### 4. Полная опись публичных маршрутов

**39 публичных маршрутов.** Из них принимают данные от другой системы ровно три:

| Маршрут | Источник | Состояние |
|---|---|---|
| `POST /api/billing/yookassa/webhook` | ЮKassa | работает, образец §II.0 |
| `POST /api/inbox/internal/ingest` | легаси-бот | **починен в B0** |
| `POST /api/recovery/internal/touchpoints` | легаси-бот | починен тем же резолвером |

Остальные 36 — вход, публичные чтения, онбординг. Опись велась от полного
списка `@Public()`, а не от ожидаемых имён: именно так в Phase A был пропущен
вебхук ЮKassa.

## Часть II. Гейт схемы

### 0. Образец, который переносится

Вебхук ЮKassa уже решает ту же задачу в бою, и гейт повторяет **его форму**, а
не изобретает свою:

| Его решение | Наш перенос |
|---|---|
| тело не доказательство → перезапрос у провайдера | вебхук CRM — триггер, истина перечитывается |
| захват переходом статуса | захват события `pending → processing` |
| повторы делает провайдер | плюс собственный повтор для обработки |
| сверка раз в час подбирает пропущенное | сверка окна записей |

Единственное расхождение: у платежа есть идентификатор у провайдера, **у записи
CRM его нет** (доказано в Phase A). Поэтому захват не по идентификатору, а по
детерминированному отпечатку.

---

### 1. Хранилище событий

```prisma
model DomainEvent {
  id             String   @id @default(cuid())
  tenantId       String

  type           String   // appointment.created
  version        Int      @default(1)

  entityType     String   // appointment | client | staff
  entityId       String   // ИДЕНТИЧНОСТЬ MAYA, не внешний id
  entitySequence Int?     // порядок в пределах сущности

  occurredAt     DateTime
  receivedAt     DateTime @default(now())
  processedAt    DateTime?

  source         String   // yclients | internal_calendar | legacy_bot
  sourceRef      String?  // record_id провайдера — провенанс, не идентичность
  observation    String   // observed_existing | after_watch_started

  dedupKey       String
  payload        Json     // минимальный факт, без ПД

  status         String   @default("pending")
  attempts       Int      @default(0)
  leaseUntil     DateTime?
  lastError      String?

  tenant         Tenant   @relation(fields: [tenantId], references: [id], onDelete: Cascade)

  @@unique([tenantId, dedupKey])
  @@index([tenantId, entityType, entityId, occurredAt])
  @@index([status, leaseUntil])
  @@index([tenantId, type, occurredAt])
  @@index([tenantId, receivedAt])
}
```

### 2. Карантин неизвестных доставок

Отдельная таблица, а не `DomainEvent` со статусом: **у карантина нет
бизнес-смысла**, и смешивать его с фактами значит однажды прочитать его как
факт.

```prisma
model IngestionQuarantine {
  id           String   @id @default(cuid())
  tenantId     String?  // может быть НЕ определён — это и есть причина карантина
  source       String
  discriminator String? // resource/status из тела, если удалось прочитать
  fingerprint  String   // детерминированный отпечаток
  receivedAt   DateTime @default(now())
  reason       String   // unknown_resource | tenant_unresolved | malformed
  diagnostic   Json?    // МИНИМУМ: ключи верхнего уровня и типы, без значений ПД
  expiresAt    DateTime // ограниченный срок хранения

  @@unique([source, fingerprint])
  @@index([receivedAt])
  @@index([expiresAt])
  @@index([tenantId, receivedAt])
}
```

🔴 Из карантина **не создаётся** доменное событие, пока смысл неизвестен — это
ваше решение по §12.1, и оно вшито в форму: у таблицы нет ни `type`, ни
`entityId`.

Диагностическая нагрузка минимальна: имена полей и их типы, значения — только
неперсональные (числовые идентификаторы). Ни имени, ни телефона, ни email.

### 3. Идентичность визита

**Сегодня:** у `Appointment` уникальность только `@@unique([id, tenantId, clientId])`;
поиск по внешнему id идёт `findFirst` **в пределах клиента**. Событие из CRM
нельзя надёжно связать с одной строкой Maya.

**Предложение:**

```prisma
@@unique([tenantId, crmExternalId])   // NULL у внутренних визитов не мешает
```

Проверка на боевой базе **выполнена заранее** — ограничение встанет без
конфликтов:

| Проверка | Результат |
|---|---|
| Визитов всего | 18, все `source = external` |
| С внешним id | 18 |
| Дубликатов `(tenantId, crmExternalId)` | **0** |
| Без внешнего id | 0 |

Провайдер в ключ не входит намеренно: `CrmIntegration.tenantId` — `@unique`,
то есть у арендатора одна интеграция, и пара уже однозначна. Если когда-нибудь
интеграций станет несколько, это будет **отдельный** гейт, а не колонка «на
будущее».

### 4. Безопасность по арендатору

- у `DomainEvent` — `tenantId` обязателен, каскад от арендатора;
- уникальность **внутри** арендатора: `@@unique([tenantId, dedupKey])`, а не
  глобальная — иначе два салона с одинаковым `record_id` подавили бы друг друга;
- `IngestionQuarantine.tenantId` **необязателен** осознанно: не определить
  арендатора — законная причина карантина, и запись об этом нужна;
- составные внешние ключи `(id, tenantId)` — как в главе 2, если события начнут
  ссылаться на сущности.

### 5. Провенанс

`source` + `sourceRef` + `receivedAt` + `observation` отвечают на вопрос
«откуда Maya знает». Сырое тело провайдера **не хранится**: в главе 2 доказано,
что `raw` читается решениями и потому протекает. Для разбора хватает карантина
с ограниченным сроком.

### 6. Детерминированные ключи дедупликации

```
dedupKey = sha256(source | entityType | entityId | type | stateFingerprint)
```

`stateFingerprint` — канонический снимок значимых полей (мастер, время, состав
услуг, присутствие). Ровно то, что легаси уже делает в `record_state`, только
переживающее смену владельца.

Времени в ключе нет: два одинаковых чтения обязаны дать один ключ.

### 7. Три времени

| Поле | Обязательно | Смысл |
|---|---|---|
| `occurredAt` | да | когда изменилось в бизнесе |
| `receivedAt` | да, `default(now())` | когда Maya приняла |
| `processedAt` | нет | когда обработала |

Совпадающими не считаются: измерено, что доставки приходят пачками, а
`create` и `update` одной записи разделяют десятки минут.

### 8. Версионирование

`type` (без номера) + `version` (целое). Номер отдельной колонкой, иначе его
нельзя фильтровать и индексировать. Смена формы нагрузки — новая версия; старые
события остаются читаемыми.

### 9. Статусы обработки

`pending → processing → processed | failed | dead`, плюс исходы приёма
`duplicate` и `stale`, которые до `DomainEvent` не доходят и считаются на
приёме. Ни один исход не молчит.

### 10. Повтор и аренда

`attempts`, `leaseUntil`, `lastError`. Захват — `FOR UPDATE SKIP LOCKED` с
арендой: упавший обработчик освобождает событие по истечении аренды, а не
держит его вечно. Отступ между попытками растёт; после предела — `dead` и
видимая метрика, а не тишина.

### 11. Индексы

| Индекс | Зачем |
|---|---|
| `@@unique([tenantId, dedupKey])` | дедупликация, переживающая перезапуск |
| `[tenantId, entityType, entityId, occurredAt]` | история сущности и порядок |
| `[status, leaseUntil]` | выборка обработчиком |
| `[tenantId, type, occurredAt]` | будущие потребители и отчёты |
| `[tenantId, receivedAt]` | наблюдаемость, возраст необработанного |

### 12. Первичное наблюдение

`observation` на каждом событии + отметка начала наблюдения на арендатора.
Предложение: **не отдельная таблица**, а поле в `CrmIntegration`
(`watchStartedAt`) — интеграция и есть момент, с которого Maya смотрит.

Первое сканирование даёт `observed_existing`; глава 4 не должна считать это
«создано сегодня».

### 13. Метки сверки

`source = 'reconciliation'` не вводим: сверка не отдельный источник, а
**способ** узнать. Вместо этого `ingestionMethod` в нагрузке провенанса:
`webhook | reconciliation | bootstrap`. Событие, найденное сверкой, имеет тот же
`dedupKey`, что и пришедшее вебхуком, — значит повторного факта не возникнет.

### 14. Хранение

`DomainEvent` — не удалять автоматически. Предложение к утверждению: через
N месяцев усекать `payload` у обработанных, сохраняя факт, тип и времена.
`IngestionQuarantine` — `expiresAt` обязателен, срок короткий: это диагностика,
а не история.

Конкретные сроки — ваше решение; в гейт вшита только **возможность**.

### 15. Наполнение (backfill)

**Backfill событий не делается.** Событие означает «Maya получила доказательство
изменения»; сочинить его задним числом из текущего состояния — значит соврать о
времени и о наблюдении.

Существующие 18 визитов остаются как есть; при первом сканировании они получат
`observed_existing`, если и когда сканирование будет включено.

Единственное наполнение — `CrmIntegration.watchStartedAt` для существующей
интеграции: значение = момент применения миграции.

### 16. Откат

| Объект | Откат |
|---|---|
| `DomainEvent`, `IngestionQuarantine` | `DROP TABLE` — таблицы новые, потребителей в проде нет |
| `@@unique([tenantId, crmExternalId])` | `DROP CONSTRAINT`, данные не меняются |
| `CrmIntegration.watchStartedAt` | `DROP COLUMN`, поле nullable |

Разрушающих операций в миграции нет: только `CREATE` и `ADD`. Ни одной колонки
не удаляется, ни один `NOT NULL` не навешивается на существующие данные.
