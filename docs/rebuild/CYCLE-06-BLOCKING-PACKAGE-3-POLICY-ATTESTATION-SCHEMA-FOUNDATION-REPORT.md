## Additive Contract

`ActionExecution` now has the six nullable rollout fields required by the gate:

| Field | Durable purpose |
|---|---|
| `policyContextContract` | Versioned contract for the server-derived decision context |
| `policyContextHash` | Hash binding the normalized policy context to the execution |
| `policyEvidenceJson` | Safe structured codes and opaque/versioned evidence references |
| `policyEvaluatedAt` | Time at which the canonical policy facts were evaluated |
| `policyValidUntil` | Claim-time freshness horizon for mutable policy facts |
| `approvalBindingHash` | Hash binding approval to the complete immutable approval subject |

Migration:

`maya-saas-backend/prisma/migrations/20260829120000_action_execution_policy_attestation/migration.sql`

The migration is additive. Existing rows remain valid only through an all-null
rollout tuple. A participating row cannot persist a partial attestation: all six
fields must be populated together, text values must be nonblank,
`policyEvidenceJson` must be a JSON object, and `policyValidUntil` must be later
than `policyEvaluatedAt`.

Nullable rollout compatibility is not permission to dispatch without an
attestation. The future Package 3 runtime contract must fail closed before
`READY` or `PENDING_APPROVAL` when its participating policy version cannot write
the complete tuple.
