# Explicit BI request: explain one published financial snapshot

The tenant-wide owner's explicit web command **«Объясни последний опубликованный финансовый отчёт»** (also «Покажи последний опубликованный финансовый отчёт») now reaches the existing C9 Business Intelligence domain through an actual published C7 `MeasurementRevision`. The response explains the source's money labels, period, timezone, observation date and missingness. It explicitly describes an `as_reported` snapshot, not current cash or an inferred cause of revenue change. **Local development checkpoint; NOT_ISSUED.**

## Existing owners and authority

`React AChat` → `AiCoreService` persisted explicit user turn → existing `C9Orchestrator.explainFinancialReport` → existing tool policy and C7 finance viewer → one tenant-wide published `business_period` metadata address → existing `C9WorkService` / `C9ContextService` / `C9Sources` → current `MeasurementReadService.snapshot` → `C9Agents.answer(BUSINESS_INTELLIGENCE)` → one reply.

The source query excludes branch, Client, appointment, staff and private configuration subjects, and uses an immutable run-admission cutoff plus deterministic publication order. It does not create a C7 measurement, discover live CRM facts, claim an OwnerReportRun was delivered, or fabricate a C7 reference from a live response. The current viewer and tool entitlement are required even for an empty selection. Branch-scoped owners, unsupported actors and revoked finance access cannot broaden the source scope.

The existing receipt freezes exact `inputEvidenceRefsJson`; retry checks that receipt before discovery. New publications do not replace the earlier choice. Expired, missing, cancelled and held work stop instead of silently selecting another source or retrying uncertain work. Work retention is capped by the source's existing validity/retention, and resultJson contains only mode/count/digest metadata, not financial metrics. The existing AC6 purge stops the run before child cleanup. No new schema or retention class was introduced.

The last source/context read repeats current authority immediately before synchronous composition. C9 does not calculate totals, currency conversion, growth, causal effects or profit. The existing C7 formatter is reused through a parts projection; its existing `measurementText` output is unchanged. The 800-character AgentResult finding bound limits displayed metrics while reserving period/asOf, historical, completeness and profit caveats, with a visible omission warning. This is a bounded explanation, not all metrics of a multi-currency report.

BI remains read-only: no strategy revision, proposed action, owner handoff or business mutation is created. A C9 run remains in its existing non-strategy state; the settled READ receipt is the completion evidence, not a new strategy lifecycle. Mixed, branch-specific, recurring and sending requests do not match this narrow exact command. Existing ordinary financial tool reads remain intact.

## Limits

This is an explicit published-snapshot explanation, not broad BI model quality, causal diagnosis or a live financial dashboard. Exact commands, tenant-wide owner scope and bounded displayed metrics are intentional limits. Fixtures are synthetic; no real-model, YCLIENTS, production, SMS/phone, HTTPS, notification, campaign or mobile-device acceptance is claimed. Business side-effect checks observe AE/C7/strategy counts and no external fetch; they are not a complete write census over all business tables. No C10 initiator, background authority, agent v2 or second orchestrator exists in this change. First Client binding and full inbound Admin routing retain their separate product/ingress decisions.
