## Поведение

Под непрочитанным уведомлением появилась кнопка «Отметить прочитанным».
Открытие ленты и переключение фильтра ничего не записывают. Пока запрос выполняется,
повторное нажатие и обновление заблокированы, а уведомление остаётся непрочитанным.
Подтверждение показывается только после свежего чтения серверного состояния именно
выбранного уведомления. Фильтр «Непрочитанные» обновляется по этому состоянию.

Используется существующий `POST /inbox/:id/read` → `InboxService.markRead`.
Владелец записи проверяет текущие tenant, user, id и `deletedAt: null`; изменяется
только `readAt`. Backend product code, роли, схема и миграции не менялись.
Персональный CLIENT не получил бизнес-доступ к Inbox.

Ответ `{ok:true}` сам по себе не доказывает запись: существующий backend возвращает
его и при отсутствии подходящей строки, не раскрывая чужие данные. Поэтому carrier
перечитывает `GET /inbox`. При потерянном/неверном ответе выполняется только такое
чтение, без прикладного повтора POST. Чужой/исчезнувший ID либо всё ещё непрочитанная
строка не дают сообщения об успехе. Отказ доступа или неуспешное перечитывание
очищают данные; закрытие, смена workspace/session и dispose отсекают поздний ответ.

Путь записи конечный: только `/inbox/{validated-id}/read` с ASCII ID длиной 1–160.
Транспорт сохраняет существующую авторизацию, включая один refresh при 401.
Произвольные URL, другие Inbox-команды и служебные источники не разрешены.
Это отметка прочтения, не Save/bookmark, завершение задачи, согласие на сообщения
или полномочия Action Engine. Никакой новой booking authority нет.

## Потеря ответа и повторная доставка

Искусственный обрыв соединения выявил повторную HTTP-доставку самим Chrome:
три логических Fetch-запроса соответствовали четырём доставкам на тестовый сервер.
Начальный тест ошибочно приравнивал число доставок к числу запросов приложения.
Диагностика и исходный неуспешный результат сохранены отдельно.

Final proof оставляет тот же обрыв после сохранения отметки, проверяет отсутствие
прикладного повтора и отдельно фиксирует доставку. Backend proof подтверждает, что
повторные и конкурентные доставки затрагивают только `readAt` того же доступного
уведомления, без создания строк, задач или сообщений. Существующая семантика
обновляет время при повторе; immutable first-read timestamp и exactly-once HTTP
не заявляются. Возврат после закрытия читает фактическое состояние, а не обещает
откат уже отправленной записи.

## Граница этапа

Закрыт только явный read acknowledgement в существующей ленте. Save, отдельные
категории салон/возможности, generic media, новые calendar entry и Ideas-to-task
по-прежнему требуют своего установленного контракта; этот этап их не разрешает.

Это **scoped local checkpoint, не release certification**. Семь SKIP остаются
SKIP. Полный backend/Platform CI, полный release mutation corpus, Xcode signing,
установка и реальная приёмка салона в этот проход не выполнялись.

Production, сохранённая база салона, Keychain, реальные providers и модель не
использовались. Deploy, миграции, grant, OTP/YCLIENTS, push/merge и установка на
iPhone не выполнялись; C10 не начинался. Документы архивируются отдельным коммитом
после проверки без изменения проверенных product bytes.
