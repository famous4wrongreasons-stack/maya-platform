## Owners and constraints

- `AiCoreService` uses the current persisted web user turn. `C9Store.conversationReadRun` derives immutable event age from TimelineStore; no background authority token is fabricated. No scheduler, C10 initiator, new policy store, new orchestrator or agent framework was added.
- `C9OccupancySource` is a narrow projection, not a fact owner. It reuses `OpportunityLifecycleRepository` and the extracted existing `readOpportunityCurrentCapacity` reader used by the C5 runner. Current C9 principal, active owner membership, source tool policies and entitlements are checked before source access and again after CRM reads. Branch-scoped owners fail closed in this first slice. Provider slots explicitly belonging to another branch cannot confirm the interval.
- One candidate is evaluated per run. The repository fetches at most two to expose `hasMore`; matching the C5 opaque appointment reference scans at most 500 appointment IDs plus one sentinel, never customer data. A missed match is `INCOMPLETE`, not proof of absence. Source calls have a finite six-second wait inside the existing logical READ lease; there is no polling, pagination loop, retry or automatic follow-up.
- Source outcomes distinguish `AVAILABLE`, `OCCUPIED`, `EXPIRED`, `CLOSED`, `STALE`, `INCOMPLETE`, `UNAVAILABLE` and `NONE`. An empty C5 result does not prove no CRM cancellations. Outages remain `unavailable` in the actual AgentResult. The source's cancellation/removed state never proves the author or reason for cancellation.
- A proposal is saved through the existing C9 strategy owner **before** the work receipt settles. Thus settled replay has exactly one immutable version; concurrent replay cannot win a different no-action proposal. Restart reuses this version and labels the answer historical, never current availability. Interrupted dispatched/held work is refused without redispatch. Cancellation, expired request identity or revoked authority also refuse reuse through existing C9 guards.
- C9 work receipts retain only outcome/provenance metadata, source refs, source digest and observed time; the raw interval is invocation-local. Proposal dates use the existing encrypted C9 plan-step intent. The existing C9 derived retention and erasure owners remain unchanged; the existing erasable TimelineStore saves the assistant reply. No new schema, migration, source-content lifecycle or retention duration was added.
- Opportunity/AgentTask references remain their actual source types. No live CRM result is represented as a C7 measurement or C8 prediction. The C9 capability registry/hash and the certified 127-code denial projection remain unchanged. Existing semantically matching `source_reader_authority` and `context_fact_source_unavailable` denials are reused. The semantic taxonomy adds one explicit partial intent (87 total); the test asserts its exact readiness/role/tool contract rather than relaxing a limit.
