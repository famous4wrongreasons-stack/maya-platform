## Processing boundary

- The existing `GoodsPhotoService` still checks current tenant/actor/owner/source before and after extraction. Original bytes and unreviewed rows are not persisted. No TeamAttachment, document store, model image transport or new schema is added.
- `GOODS_PHOTO_OCR_PROVIDER` is a closed server setting: absent/`disabled` keeps the existing unconfigured refusal; `apple_vision` opts into the local Mac implementation. An unsupported platform or absent helper refuses. There is no remote, paid or automatically installed fallback.
- From the backend working directory, compile the fixed reviewed helper with `npm run build:ocr:vision` **after** the normal backend build, which may replace `dist`. The helper lives at the fixed `dist/ocr/goods-photo-vision` path. The build uses installed Swift/frameworks and no package manager/download. This checkpoint enabled only its isolated proof instances, not production.
- Native execution has no shell or caller path/URL arguments. Normalized PNG travels through stdin and bounded JSON through stdout. The child receives only PATH/LANG/LC_ALL, not inherited credentials. Raw OCR text and native error descriptions are not logged or returned as diagnostics.
- Input is at most 2 MiB, single-frame PNG/JPEG/WebP, at most 12 million pixels; normalized output is at most 2600×2600 and 16 MiB. Sharp has a five-second processing timeout. Native output is at most 256 KiB, diagnostics at most 4 KiB, and native execution has a 15-second timeout with kill/reap before settlement. One parse may run per Node process; excess work fails busy without a queue. These are finite bounds, not a hard process RSS quota or distributed concurrency guarantee.
- Owned byte buffers are cleared after use. Native/framework allocations and JavaScript strings are not claimed to be securely erased. The recognizer code has no file/network API for document storage/transport; proof Node network hooks do not constitute an OS-wide native egress measurement.
- Supported layout is deliberately narrow: one horizontal five-column header (name, quantity, unit, price, total), one to twenty single-line rows and an optional final total footer. Header aliases are explicit in `goods-photo-ocr-rows.ts`; wrapping, overlapping/ambiguous geometry, multiple tables and excess rows refuse. Unknown numeric cells remain null. No inferred currency, price meaning, arithmetic, matching or business action is introduced.
- Current React distinguishes unavailable configuration, busy recognition, recognition failure and unsupported table from CRM-source errors. Search/detail/review and UNKNOWN semantics retain their existing owners. Rendering an error dispatches no action.
