## Behavior and boundary

- Server configuration is closed to `disabled` (default), `apple_vision` and `tesseract`. Clients cannot select a binary, language, URL, model or native option. The prior Mac profile remains available.
- The Tesseract port uses fixed platform paths (`/usr/bin/tesseract` on Linux), stdin PNG and stdout TSV, no shell, fixed `rus+eng`, LSTM mode, single block segmentation and one OpenMP thread. Its environment contains only PATH, LANG, LC_ALL and the two thread bounds. No inherited provider credentials, retry, remote fallback or request-time installation/download.
- The existing two-MiB input, twelve-million-pixel single-image decoder, 2600-side normalized PNG, five-second decoder deadline, fifteen-second native deadline, 256-KiB output, four-KiB diagnostics and single in-flight parse bounds remain. Kill/close precedes settlement; stderr and owned image/output buffers are cleared. These are finite limits, not a hard native RSS quota or a distributed queue policy.
- Assets have exact sizes and SHA-256 checks before native admission, bounded file reads and refusal of symlink asset directories/files and multiply linked models. Build artifacts must remain immutable to the running service. There is no untrusted asset-upload endpoint.
- TSV coordinates come from measured engine word boxes and a separate `maya.tesseract.words/1` protocol; they are not fabricated Vision coordinates or injected invoice rows. Malformed/multipage/oversized TSV refuses. The supported table remains one horizontal five-column header, one to twenty single-line rows and optional final total.
- Engine scores are uncalibrated. Weak numeric cells stay null; weak name/header refuses. Unknown unit literals stay null, without spelling correction or catalog-unit inference. A narrow literal allowlist is deliberately incomplete. Even a high OCR score does not prove text correct. Price meaning and row confidence remain null; no arithmetic, currency, canonical item, unit conversion or automatic matching is inferred.
- Current tenant/actor/source checks remain with `GoodsPhotoService` before and after extraction. All rows require review and remain `recognition_acceptance: NOT_ACCEPTED`. Original documents and unreviewed extraction are request-local; no new schema, history/attachment owner, retention, approval, CRM writer, notification or background initiator is introduced.

## Packaging and dependency choice

Use the existing native Tesseract CLI rather than a new WASM/Node worker dependency. The current installed development engine is 5.5.3; the Alpine 3.23 metadata examined during preparation names 5.5.1-r0. These are different runtimes, not an equivalence claim.

Two official [tessdata_fast models](https://github.com/tesseract-ocr/tessdata_fast/tree/87416418657359cb625c412a48b6e1d6d41c29bd) are pinned to commit `87416418657359cb625c412a48b6e1d6d41c29bd`, exact byte lengths, Git blob digests and SHA-256 in [the manifest](../../maya-saas-backend/scripts/goods-photo-ocr-models.json). English and Russian total **7,974,826 bytes (7.61 MiB)**, plus an 11,358-byte Apache-2.0 license. This model transfer and local processing have no provider API charge. Engine dependencies have their own recorded licenses; the whole native stack is not described as Apache-only.

`npm run prepare:ocr:models -- --fetch` is an explicit build/developer action; `--verify` is offline. The script accepts no custom location, refuses redirects, bounds three fixed downloads, verifies before atomic publication and never implicitly replaces invalid assets. The Docker builder prepares models; the runner installs `tesseract-ocr`, copies and verifies models. Large standard-language APKs are not requested. The image and `.env.example` leave OCR disabled until explicitly selected. Downloaded binaries/models are excluded from Git and the build context.

The existing `node:24-alpine` tag and APK resolution remain mutable. Official metadata provides only a dependency budget, not an installed-image measurement. No Docker/Podman/Colima runtime is available locally, and no VM was installed. Before a Linux release, build/run the exact candidate and record image digest, architecture, package versions/licenses, offline image recognition, resource and cleanup evidence. The Mac executable proof does not close this gate.
