# Подключение YCLIENTS: отличие прежнего пути от текущей проверки

Проверенные исправления сохранены в `146c2573ac31f48b8b82d09bffa0db5f22386c96`; исполняемый source — `b46e3d09748d6e38549fcaeb3cb0565077f77345`. [20 HTTP cases, текущий React и restart](evidence/maya-yc-pre-ae400-reproduction-20261010/summary.json) квалифицированы только на synthetic transport. Реальное подключение владельца пока не сохранено.

**История подтверждает отдельную проверку доступа к выбранной компании, но не доказывает её недавнюю регрессию.** Native `testConnection` сменил прямое чтение staff на поиск компании в `companies?my=1` ещё **31 июля**, commit `9f647fe39f14da0eb637e383b93d0c9f0a918895`. Параметр `my=1` появился в `aa0048af96a6297adecf29a09c4a65ec6934f35f`. Ни локальная форма 10 октября, ни сегодняшняя правка не ввели этот endpoint или формат авторизации.

Прежняя работавшая интеграция и новая локальная регистрация относятся к разным состояниям приложения. Документ от 05.10 описывает active/live серверную интеграцию; бизнес текущего локального owner создан отдельно 10.10. В него не переносились production integration или credentials. Поэтому пустое локальное подключение не является свидетельством удаления прежней интеграции. Её сегодняшнее серверное состояние здесь не проверялось.

## Что известно об отказе владельца

На `bcb5246a6937a96322130ddbca729ff0eb0988dd` были два connect HTTP 400 после companies HTTP 200 с **`provider_response_read`**. Это сильнее одного статуса 200: соответствующий transport уже разобрал ограниченное JSON-тело, не отметил `success:false`, не отказал по scope/redirect/budget и передал ответ native adapter. Следующих catalog/team reads нет. Source локализует отказ в `connection_check`, до AE admission. Recovery `NOT_OBSERVED` и read-only metadata подтверждают отсутствие installation. [Закрытые факты](evidence/maya-owner-yc-connect400-20261010/summary.json).

Поэтому нет основания объяснять этот случай отсутствующим partner token, заблокированным checkbox, отсутствующим idempotency key, чужим branch, HTTP 401/403 провайдера или недопущенным route: такие границы должны остановить запрос раньше наблюдённого completed companies read. Это не утверждение, что credentials имеют все необходимые provider права, и не доказательство наличия выбранной компании в ответе.

**Один отсутствующий redacted факт для дальнейшего разделения причин — canonical `error.code` исходного connect HTTP 400.** Старый observer его не сохранил. На точном `bcb5246a` runtime создавал Nest с `logger:false`, а launcher игнорировал stdout/stderr дочернего backend; обычный service warning также не образовал сохранённый диагностический лог. Его нельзя восстановить из HTTP200/400, последнего draft формы или synthetic PASS. Даже `crm_company_not_found` на старом source мог обозначать как отсутствие компании, так и ошибку разбора display fields, поэтому один код ещё не гарантирует окончательную root cause. Закрытая allowlist-диагностика добавлена для будущего отдельно допущенного сеанса; новой попытки или ввода ключей ради получения этого факта не запрашиваем.

## Свидетельства и пределы

- [Исторический production summary от 05.10](WEBSITE-GUEST-ONE-RECORD-ACCEPTANCE.md): active integration и отдельные authenticated provider reads; это документарное свидетельство. Отдельный raw receipt этой пары в доступном локальном архиве не найден, как зафиксировано в [pilot preflight](MAYA-SINGLE-SALON-PILOT-PREFLIGHT-20261010.md). Он не доказывает version/runtime или успешный connect именно текущей формы.
- [Локальная owner registration](evidence/maya-owner-registration-20261010/summary.json) и [закрытый connect outcome](evidence/maya-owner-yc-connect400-20261010/summary.json) сохраняются отдельно.
- [Native history и source hashes](evidence/maya-yc-connection-differential-20261010/native-history.json), [независимая проверка differential](evidence/maya-yc-connection-differential-20261010/review.json).
- Только repo history, source и уже сохранённые sanitized reports. Никаких новых runtime/tests, owner DB/credentials, provider/model calls, site/production changes или восстановления legacy bypass.
- Исправления сохранены локально. Push в рабочую GitHub ветку дважды отклонён automatic approval review: переданное позднее разрешение не признано trusted user text. После единственного идентичного retry дальнейших попыток и обхода не было; публикация заблокирована отдельно от диагностики.
