# YCLIENTS goods: exact current source port

The existing `CrmService` and `YclientsCRMAdapter` now expose a bounded internal `readGoodsItem` port. It performs one current exact-ID GET, requires one matching item, and keeps sale price, cost price, per-unit cost, sale/write-off units and their ratio separate as decimal strings. Missing currency/prices/units remain unknown; no cached/search/local-inventory fallback, stock balance, supplier, OCR confidence or mutation is inferred. Current tenant scope and active external adapter are required. An internal-calendar tenant refuses this external source path.

This is useful source groundwork for the already requested photo-goods workflow, not a chat-reachable completed feature. No AI tool/controller/action, schema, persistent draft/photo, new store or authority was registered. Future ingress must enforce current actor/feature/branch rights. `as_of` is read observation time, not the provider's modification time. The provider goods endpoint can also return certificate/subscription items: item kind is not qualified for a future physical-goods write by this projection.

[Evidence](evidence/maya-development-integration-20261006/yclients-goods-read/archive.json): **153 tests in 3 suites PASS**; production and complete widget-probe types PASS; scoped lint and 5 domain-boundary checks PASS. Tests cover exact source identity, fresh changed prices, zero versus unknown, separate units/prices, malformed/ambiguous values, invalid route identifiers before dispatch, tenant mismatch before adapter and unavailable/internal-source refusal. Adapter fetch is mocked; all new goods dispatches are GET. No live provider, model, HTTP product ingress, OCR or write/readback acceptance is claimed. Independent read-only review found no blocking defect.

[Complete API capture inventory](evidence/maya-development-integration-20261006/yclients-api-inventory/operations.json) enumerates **304 method/path pairs** from the public OpenAPI previously downloaded on 2026-10-07: 150 GET, 87 POST, 27 PUT, 8 PATCH, 32 DELETE. It preserves deprecated operations and query templates, marks excluded/deferred groups, and separates documentation presence, code mapping, unobserved integration rights and unexecuted provider acceptance. Only four operations have exact checkpoint mappings in this first inventory; the remaining 300 are not silently declared unsupported or unimplemented. Scope labels are engineering triage, not per-operation authorization. No new external calls were used to generate it.
