## Главные найденные проблемы

### 1. Конфликт canonical и sitemap — высокий приоритет

В sitemap перечислены отдельные страницы, но их HTML указывает canonical на главную `https://malesthetic.pro/`:

- `/booking/`;
- `/shop/`;
- `/personal-data-policy/`;
- `/personal-data-consent/`;
- `/privacy/`.

Так поисковику одновременно сообщаются два разных решения: sitemap предлагает индексировать отдельный URL, а `rel="canonical"` объявляет его вариантом главной. Google прямо рекомендует не задавать разные canonical-сигналы для одной страницы, а Яндекс считает страницу с canonical на другой URL неканонической.

Предложение: назначить каждой индексируемой странице self-canonical с её собственным абсолютным URL. `account`, checkout и 404 оставить `noindex`.

### 2. `www.malesthetic.pro` не перенаправляется — высокий приоритет

`https://www.malesthetic.pro/` отвечает 200 и показывает копию сайта. Canonical указывает на адрес без `www`, но серверного 301-редиректа нет. Кириллический домен при этом настроен правильно и перенаправляется.

Предложение: добавить 301-редирект со всех URL `www.malesthetic.pro` на соответствующие URL `malesthetic.pro`.

### 3. Перегруженная предзагрузка главной — высокий приоритет для мобильных

В HTML главной обнаружено:

- 7 предварительно загружаемых шрифтов;
- 30 предварительно загружаемых изображений;
- 5 видео с `preload="auto"`;
- 4 уникальных auto-видео суммарным размером около 16.4 МБ.

Самый тяжёлый файл — `media/interior-hq.mp4`, около 10 МБ. Это не доказывает плохие Core Web Vitals без полевых данных, но создаёт высокий риск лишнего трафика и медленной первой загрузки на мобильном интернете.

Предложение: оставить preload только для реально критического первого экрана; остальным видео задать `metadata` или `none`, изображения ниже первого экрана загружать лениво, проверить результат на мобильном профиле.

### 4. Checkout одновременно закрыт robots.txt и помечен noindex — средний приоритет

`/shop/checkout/` имеет `noindex, nofollow`, но одновременно закрыт через `Disallow`. Если робот не может загрузить страницу, он может не увидеть `noindex`.

Предложение: оставить `noindex, nofollow`, но убрать checkout из `Disallow`, затем проверить в Яндекс Вебмастере и Search Console.

### 5. Метаданные страниц недостаточно различаются — средний приоритет

`/booking/` использует тот же title и description, что главная. `/shop/` имеет отдельный title, но общее описание парикмахерской. Это снижает ясность страниц для поисковика и пользователя.

Предложение: подготовить уникальные title/description по назначению каждой страницы, без выдуманных предложений и цен.

### 6. Кэш Next.js-статики можно усилить — низкий приоритет

Хешированный CSS из `/_next/static/` сейчас отдаётся с кэшем примерно на неделю. Для файлов с хешем безопаснее длительный immutable-кэш. В каталоге также лежат артефакты нескольких старых сборок; удалять их можно только после проверки полного manifest и резервной копии.

## Рекомендуемый порядок

1. Подготовить локальный change set для canonical, `www`-редиректа и robots checkout.
2. Показать владельцу точные изменения и список затрагиваемых файлов.
3. После approval создать датированные резервные копии на Beget.
4. Загрузить только согласованные файлы, не весь `public_html`.
5. Проверить статусы, canonical, robots, sitemap и откатить изменения при несоответствии.
6. Отдельно оптимизировать тяжёлую главную и измерить мобильный результат.
