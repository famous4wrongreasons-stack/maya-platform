# Следующий шаг: отдельный HTTPS для первой проверки iPhone

Это подготовленный план, **не разрешение и не выполненная публикация**.
Код: `7aee28d297cd1d70c2f1cb6ce96740d9fd5948d3`.

1. После разрешения владельца заново проверить DNS и свободные порты.
   Добавить только отсутствующий A-record `phone-test.mayaos.ru` на выбранный
   VPS. Не заменять apex, www, api, MX, другие A/AAAA или существующие записи.
   Не менять сервер/процесс SMM.
2. До открытия сети закрыть существующую self-service trial регистрацию.
   Сохранить исходный private-bootstrap plan неизменным; подготовить отдельную
   точную closed configuration с теми же внутренними backend/DB networks,
   лимитами и запретами провайдеров. Проверить её целиком, штатный preflight,
   отказ регистрации и обычный вход. Не запускать private-bootstrap plan с
   публичными портами и не превращать preparer в универсальный override API.
3. Открыть только canonical gateway для этого hostname на 80/443 и получить
   настоящий доверенный TLS. Backend/DB host ports остаются закрытыми. Проверить
   сертификат без TLS bypass, текущие PWA/callback bytes, readiness и native CORS.
4. Повторить сравнение образа, кода, ресурсов, SMM PID/start/restarts/unit hash.
   Внешние провайдеры backend по-прежнему недоступны. `widgets.runtime` не выдан.
5. Заново проверить development signing/provisioning и подписать уже проверенный
   React/Capacitor payload для exact API `https://phone-test.mayaos.ru/api`.
   Только после отдельного разрешения установить на iPhone: `ru.mayaos.app`
   может заменить имеющуюся Maya. Проверить WebView, клавиатуру, разделы,
   возврат из фона, обычный вход/выход и видимые отказы недоступных функций.

Два автоматически созданных аккаунта — одноразовые synthetic proof accounts;
их случайные пароли в отчёте не хранятся. Доступ владельца к телефонному smoke
нужно подготовить через обычную регистрацию/авторизацию до закрытия bootstrap,
без изменения ролей или обхода auth. Пароль не передаётся в чат/логи.

При проблеме остановить только `maya-phone-staging`, не удаляя volumes; убрать
только созданную тестовую DNS-запись/публичный listener, сохранить receipts и
проверить SMM. Не останавливать общий Docker и не очищать firewall.

Первый smoke проверяет приложение на synthetic data. Живые ответы модели,
история салона, Telegram, голосовые провайдеры и booking не становятся
разрешёнными от публикации тестового HTTPS. Для них сохраняются отдельные
действующие допуски и штатные identity/AR-1/Action Engine проверки.


## Уточнение владельца — 15 октября: первая полезная проверка на реальном салоне

Владелец предложил перейти сразу к настоящим данным. Synthetic server proof
уже завершён и сохраняется как техническое доказательство; отдельный ручной
прогон владельца на вымышленном салоне не является обязательной целью.
Следующая подготовка должна рассмотреть настоящий салон в режиме чтения:
услуги, цены, категории, мастера, адрес и часы. Это предложение минимального
объёма, не разрешение переносить всю базу клиентов/журнал или выполнять booking.

Проверено из текущего source/evidence:

- В закрытом Beget proof CRM integrations = 0; реальные ключи не переносились.
- Сохранённые ключи Mac обслуживаются существующим Keychain helper только
  в привязанном локальном сеансе. Его нельзя считать установленным удалённым
  хранилищем или автоматически переносить его полномочия на Beget.
- Локальное ограничение YCLIENTS setup/catalog reads реализовано отдельным
  launcher/transport с exact company и allowlist. Нормальный compiled main на
  Beget сейчас внешней сети не имеет. Простое открытие сети/добавление ключа
  не доказывает запрет provider writes; удалённый путь требует отдельной
  проверки границ через существующих CRM/credential owners.
- Личная история требует canonical verified Client, current consent/settings
  и соответствующего источника визитов. Существующая синхронизация 14-дневного
  журнала читает записи других клиентов тоже. Не описывать её как импорт
  исключительно личной истории и не переносить локальную БД целиком молча.

Подготовить один согласованный сценарий на реальном салоне, точное хранение
ключей и допускаемые чтения до запроса разрешения на внешнее исполнение.
Доступ к модели и бюджет, персональные данные и provider mutations не следуют
автоматически из выбора настоящих названий услуг. DNS/publication, установка,
реальные обращения и перенос данных этим уточнением не выполнены.

## Подготовленное следующее действие после регистрации владельца

Владелец зарегистрировал обычный аккаунт на отдельном стенде. Регистрация новых
салонов уже закрыта и проверена по canonical `self_serve_signup_disabled`.
Подписанная сборка для iPhone использует `https://phone-test.mayaos.ru/api`.
Реальная связь YCLIENTS ещё отсутствует.

Нужен один явный допуск на конкретный новый адрес хранения ключа и публикацию
стенда. Прежнее сохранение в Связке ключей разрешало локальный Mac, а не этот VPS.

- Источник: только сохранённый партнёрский ключ YCLIENTS через уже проверенный
  MayaLocalCredentials helper. DeepSeek не читается и не переносится.
- Получатель: выбранный владельцем Aspiring Eduard, `45.67.56.4`, только
  `/srv/maya-phone-staging/private/catalog.env`, root-only 0600 вне application
  payload/Git. Передача через проверенный SSH из памяти, без вывода значения,
  CLI-аргументов, журналов или изменения keychain ACL. Перед исполнением требуется
  отдельный конкретный допуск владельца; новый срок не берётся из старого permit.
- Пользовательский токен: один ввод владельцем через штатный закрытый экран
  A17; normal owner login, exact company `503759`, собственный филиал, проверка
  версии/idempotency и canonical encrypted storage. Не копировать retained DB,
  её `User`/`Client`/history/authority rows или обходить A17 через SQL.
- Сеть данных: bounded catalogue relay, максимум 40 GET за окно до 24 часов,
  без автоматического продления/перезапуска. Только услуги/категории/мастера и
  данные компании; management staff source может содержать контакты сотрудников.
  Реестр клиентов, журнал, booking, сообщения и модель остаются закрытыми.
- Доступ телефона: добавить только A-record `phone-test.mayaos.ru` →
  `45.67.56.4`, открыть exact test gateway HTTPS с проверяемым сертификатом.
  Проверить отсутствие конфликтующей записи до добавления. Не менять apex,
  www/api, почту, существующий сайт, SMM или публичные настройки production Maya.
  Backend/DB остаются без host ports и прямого выхода в интернет.
- Перед проверкой подтвердить закрытую регистрацию, tenant/profile refusals,
  неизменный SMM и PWA/native bytes. `widgets.runtime` не выдаётся. Установка
  `ru.mayaos.app` и реальные бизнес-действия остаются отдельными шагами.

Это описание подготовленного действия, не receipt передачи ключа/публикации,
не новый AR-1 и не автоматическое разрешение remote export из локального permit.
