# Следующий шаг: отдельный HTTPS для первой проверки iPhone

Это подготовленный план, **не разрешение и не выполненная публикация**.
Код: `7aee28d297cd1d70c2f1cb6ce96740d9fd5948d3`.

1. После разрешения владельца заново проверить DNS и свободные порты.
   Добавить только отсутствующий A-record `phone-test.mayaos.ru` на выбранный
   VPS. Не заменять apex, www, api, MX, другие A/AAAA или существующие записи.
   Не менять сервер/процесс SMM.
2. До открытия сети закрыть существующую self-service trial регистрацию.
   Сохранить исходный private-bootstrap plan неизменным; подготовить отдельную
   точную closed configuration с теми же внутренними backend/DB networks,
   лимитами и запретами провайдеров. Проверить её целиком, штатный preflight,
   отказ регистрации и обычный вход. Не запускать private-bootstrap plan с
   публичными портами и не превращать preparer в универсальный override API.
3. Открыть только canonical gateway для этого hostname на 80/443 и получить
   настоящий доверенный TLS. Backend/DB host ports остаются закрытыми. Проверить
   сертификат без TLS bypass, текущие PWA/callback bytes, readiness и native CORS.
4. Повторить сравнение образа, кода, ресурсов, SMM PID/start/restarts/unit hash.
   Внешние провайдеры backend по-прежнему недоступны. `widgets.runtime` не выдан.
5. Заново проверить development signing/provisioning и подписать уже проверенный
   React/Capacitor payload для exact API `https://phone-test.mayaos.ru/api`.
   Только после отдельного разрешения установить на iPhone: `ru.mayaos.app`
   может заменить имеющуюся Maya. Проверить WebView, клавиатуру, разделы,
   возврат из фона, обычный вход/выход и видимые отказы недоступных функций.

Два автоматически созданных аккаунта — одноразовые synthetic proof accounts;
их случайные пароли в отчёте не хранятся. Доступ владельца к телефонному smoke
нужно подготовить через обычную регистрацию/авторизацию до закрытия bootstrap,
без изменения ролей или обхода auth. Пароль не передаётся в чат/логи.

При проблеме остановить только `maya-phone-staging`, не удаляя volumes; убрать
только созданную тестовую DNS-запись/публичный listener, сохранить receipts и
проверить SMM. Не останавливать общий Docker и не очищать firewall.

Первый smoke проверяет приложение на synthetic data. Живые ответы модели,
история салона, Telegram, голосовые провайдеры и booking не становятся
разрешёнными от публикации тестового HTTPS. Для них сохраняются отдельные
действующие допуски и штатные identity/AR-1/Action Engine проверки.
