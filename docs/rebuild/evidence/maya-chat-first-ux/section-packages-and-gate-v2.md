## Implementation packages, waves and the completion gate

**16 capability packages across 6 waves**, replacing the 30-package / 6-wave proposal. Wave 1 (2 packages) is the only wave executable under this cycle's architecture-only fence. Waves 2–6 do not open until the Wave-1 exit gate is approved by a human and its hash is pinned in code the way `C9_REGISTRY_HASH` is pinned at `src/orchestration/c9.registry.ts:177`.

The cycle is declared finished by a **24-condition Finite Completion Gate** that must go green simultaneously on one commit, in one CI job named `chat-first-completion-gate`.

---

### 1. The consolidation test, and what it found

A package earns its own id only if it delivers a capability that can be exercised and proved on its own. A package cut along an artefact boundary, a taxonomy class, or a staging step is a fragment and must be merged into the capability it serves.

Applying that test to the 30:

| Consolidation | Was | Now | Reason |
|---|---|---|---|
| Ledger, canon, dossier, parity harness | P01, P02, P06, P16 | **K1** | One artefact, one human signature. P01's hash proves nothing without P06's successors; P16 is not a class, it is the proof harness that reads the ledger. |
| Contract, authority types, text minter, a11y rules | P03, P04, P05, P29 (part) | **K2** | One compiled contract with three validators. Accessibility rules are contract clauses (`reading_order`, `live_region`), not a wave-6 package. |
| Intent gateway + read-only emission | P07, P08 | **K3** | The two directions of one wire protocol, and the programme's only two new routes. Neither is exercisable alone. |
| Authority runtime + secure-surface fence | P12, P20 | **K4** | `NEVER_CHAT_ACTUATED` and `SECURE_SURFACE_ONLY` are outputs of the same derivation at the same evaluation point. |
| Shell, renderer, route registry, overlay re-expression | P09, P10, P19 | **K5** | One client surface. Text-first then rich is ordering inside a package. The route registry is shell infrastructure and must precede the widgets that escalate into it. |
| Carrier profiles + voice/multimodal | P11, P15 | **K6** | Voice is a carrier and an input modality, not an authority path; its defining proof (identical audit line across say/type/tap) belongs with the degradation receipt. |
| Class MOVE / MERGE, split by audience | P17, P18 | **K8, K10** | Class is taxonomy; audience is capability. Evidence: MOVE splits client 41 / owner+staff 47, MERGE splits client 20 / owner+staff 35 — two different canonical owner sets (booking, loyalty, profile vs C7/C8 + C9). |
| Consent, unbind, erasure | P22, P23, P26 | **K12** | One legal capability, one mechanism (`principal_proof_hash` rotation, verified-channel control), and provable only jointly: an erasure that corrupts the consent register is the failure mode. |
| Nav retirement + deletion | P21, P30 | **K16** | Retirement is removal. D8-B makes it per-row with a dark window, not per-class. |
| Attribution report | P25 | **K10** | A report over canonical `attributionStatus` facts is an analytics widget, not a restoration lane of its own. |
| Accessibility certification | P29 | dissolved | Split across K2 (rules), K5 (renderer branches, keyboard), G22 (end-to-end audit). It was already described as "not a wave". |
| **Proactive and notification integrity** | *(none)* | **K13 (new)** | G16 was asserted with no package behind it, and the scheduler (32), web-push (16), sms (3) and email (1) channels — 52 of the 135 undispositioned surfaces — had no owner. |

Not consolidated, because dependency or proof structure genuinely forbids it: **K7 booking** (its safety property is a static-analysis proof over the minting code, destroyed if other minting paths land in the same change), **K11 C9 binding** (must be provable as 0 contract diffs against shipped orchestration), **K14 Telegram cutover** (~45 individually recorded command decisions, not batchable).

**[NON-NORMATIVE] Why this order.** Wave 1 first because 135 surfaces have no class, and a class with no membership has no successor and is therefore un-deletable forever. K3 before any renderer because the gateway is the one component whose absence silently converts the design into the thing it forbids — once the wire format has no field for an endpoint, `BUTTON → ENDPOINT` is unavailable to everyone, including a tired engineer at 2am. Read-only (Wave 2) before write (Wave 3) because a wrong read shows a wrong number and a wrong write makes a wrong booking. K4 before K7 because booking's safety property is the non-existence of a COMMIT token outside a confirmation, and non-existence is only meaningful once the minting authority is the thing deciding it. Waves 3–4 before Wave 5 because K4's fence must be closed before the consent owners exist. Cutover last, and deletion last within cutover, because all of K16's difficulty was deliberately moved into the parity proofs that Waves 2–5 produce.

### 6. [NON-NORMATIVE] What the evidence still does not settle

**The primary-nav target.** All 89 PWA primary-nav rows are dispositioned, but darkening every entry-removing disposition (RETIRE 13 + MERGE 19 + MOVE 18) leaves 39 PWA destinations, not 5. Reaching D2-A requires re-dispositioning 34 rows that currently read KEEP AS CAPABILITY, KEEP AS FULLSCREEN DETAIL or SECURITY/AUTHORITY ONLY. G11 therefore cites the ledger and the owner's adjudicated number, and K1 must produce those 34 rows or the number must change. This is a product adjudication (D2, still open), not a finding, and it is not derivable from 795 rows.

**The Telegram authority-dead mechanism.** Two of three verifiers confirmed at high confidence; the dissenter disputed causality, not mechanism. K14 is written to be correct either way: every command gets an individually recorded decision, the six fenced capabilities are checked against the HTTP surface case by case regardless, and the staging probe runs before any retirement — never in production, because the classification that would make a production probe safe is the thing the probe exists to establish.

**Out-of-repo native surfaces.** There is no native source in this repository; the Capacitor iOS shell and Android TWA load the same web bundle across a frozen plugin contract that ships on a different cadence. G23 checks that the bundle declares and respects a pinned contract version and degrades visibly rather than failing silently on an older shell. Nothing in this repository can prove the shell honours its half, and the gate does not claim to.

**The two 152-FZ exposures.** D9 recommends a separately authorised remediation lane for marketing-consent revocation and base personal-data withdrawal, because their canonical owners are already live and the gap is a missing ingress measured in days. That lane sits outside this cycle's fence, carries its own dated authorisation and rollback, and its interim route is deleted by K12 when the widget replaces it. It writes to the same append-only canonical owner, so no second source of truth is created.
