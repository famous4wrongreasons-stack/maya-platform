# Final FBE2E owner decisions

Owner decision: L2=B, L5=B, L24=B, L20=B, L23=A, L25=B, L26=A.

L2 requires blocking contract checks and complete fresh release admission. The
`widgets-mutation-ci.mjs release` command runs the contract compiler, structural
checker and K1 dossier before the existing strict full-corpus collector. A
diagnostic subset or ordinary `assemble` output is not release authorization.
GitHub repository branch protection is an external setting; source workflow
failure must not be represented as proof of that setting.

L5/L24: one next local calendar day, using selected branch/availability timezone
and tenant.defaultTimezone fallback. No widening, free-text or new input kinds.

L20 requires the real booking owner and Action Engine to receive a provider
fault naturally, over test infrastructure only. Supplying UNKNOWN is insufficient.

L23 is accepted for the final certified candidate of this bounded pass. The
structural test does not inspect every extra widget-path literal across all four
network modules. The exact route allowlist, single fetch call site, build refusal
fixtures and network ratchets remain mandatory. This acceptance does not extend
to subsequent network changes and does not authorize any additional endpoint.

L25 preserves literal delivery/render lifecycle; a selector tap alone is not
render evidence, and render evidence grants no booking or Action Engine authority.

L26: `docs/rebuild/evidence/maya-chat-first-ux/gate-audit-build.mjs` and all audit
reports it produced are archival-only and inadmissible for release certification,
including reports predating the explicit archival marker. Original historical
bytes are preserved. The strict fresh collector is the sole release-admission
path: exact source, declarations, full coverage, successful controls and normal
exits are mandatory. Manual audit summaries cannot substitute for raw receipts.

HANDOFF remains globally STOP; full-contract certification remains false.
These decisions authorize implementation and synthetic proofs only, with no
production migration, deploy, entitlement grant, OTP or YCLIENTS effect.


## Implemented current contracts (supersede limitations; not a certificate)

L5/L24 selects the authenticated tenant's active internal provider and its branch
through `AvailabilityCalendarService`, a read-only owner. External availability
uses its existing tenant timezone, which is the canonical fallback. Local date
arithmetic uses calendar components, not elapsed 24 hours. The canonical slot's
instant is unchanged; the server formats the displayed slot and confirmation in
the same timezone. No new input kinds, window widening or text interpretation.
The eight HTTP/PostgreSQL/React pipeline cases cover UTC, positive and negative
offsets, a fractional offset, leap/month/year boundaries and both DST changes.

That pipeline exposed an H1 defect: the emitter used the parallel ASCII-sorted
helper while H6 and carrier H7 use the canonical ActionIdentity codec. Opaque slot
keys can order differently (observed with Kathmandu). The emitter now imports the
existing canonical function. `L5-H1` and mutation `FB-H1-CODEC` bind the regression;
no alternate hash scheme or presentation normalization was introduced.

L25 uses the existing resolve request for an optional exact sealed observation
(widget_id, body_hash, envelope_seal). The HTTP egress owner records MINTED →
DELIVERED; the connected carrier's independent post-mount callback records
DELIVERED → LIVE. Delivery means server handoff to its HTTP channel; LIVE records
an authenticated carrier observation, not proof of human attention. Neither
observation grants authority. Current principal, tenant, seal, expiry, retention,
and release admission are reread. Conversation locking and CAS couple the state
with the existing AuditLog transaction. Foreign/expired/revoked/missing observations
refuse; duplicates are idempotent only with their exact existing audit. A selector
REFINE tap cannot create either observation. No new persistent model or column.

`L25-ATOMIC` injects a failure after the audit append and proves both the state and
audit roll back. `L25-CONCURRENT` submits eight concurrent observations and a replay,
proving one transition/audit and zero booking or Action Engine executions. The real
React browser mount is checked independently of taps, including a disposable
counterfactual bundle without the observation hook. The synthetic DOM drawer used
by source-carrier probes is explicitly disclosed; it is not human-attention evidence.

L20 uses a loopback test provider and dedicated PostgreSQL test-provider table,
without a uniqueness constraint that could conceal duplicate dispatch. The provider
commits its row and destroys the socket before response bytes. Its test transport
adapter reports the resulting connection failure via the existing CRM error contract;
the real booking owner and Action Engine derive UNKNOWN. A failing reconciliation
read retains safe pending. One ordinary and six simultaneous retries produce one
provider dispatch/row, one execution, no mirror appointment and no success line.
No UNKNOWN decision is supplied to Action Engine, and no external provider is used.
